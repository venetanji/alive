# Next Installed Help Roots: Bounded Map

Read-only study on 2026-10-22, for work after the separate append/prepend/int/float
qualification. The next useful finite set is **eight arithmetic roots plus send
and receive**. Each has a mapping for every executable class and fits the native
32-node/64-cable capacity after an exact policy for its four help helpers. The
first three arithmetic roots offer the cheapest reusable score; division and
modulo come later because the existing bounded runtime deliberately refuses
some Max results. No capacity expansion or new object family is justified by
this set.

This report adds no qualification pass. The frozen corpus denominator is 2,103;
the four-root allowlist, qualification counter, product and harness are unchanged.
No Max, product runtime, desktop, browser, screenshot or clipboard operation was
used. Installed files were parsed as data only. No installed patch graph, prose,
script or helper payload is retained here.

## Concrete Importer Barriers

**Exact source admission.** None of these ten sources is in the four-source
`ROOTS`/`sourceHashes` allowlists. The probe therefore cannot issue a trusted
identity, and the importer cannot turn their scripts into `help_helper` nodes.
Without that identity the generic path rejects the helper boxes; an importable
partial graph is not a complete installed help root. The JS `HELP_OBJECTS` and
Rust hierarchy validation also explicitly accept only append/prepend/int/float.
Changing only one list would not make a valid shared document.

**Finite helper shape.** The current recognizer additionally requires all helper
arguments to be the same single object string and the starter's source text
and saved filename to contain `helpstarter.js`. The candidate differences are
concrete and separate from source allowlisting:

| Candidate | Shape Beyond A New Hash |
| --- | --- |
| times | Symbolic `*` is used consistently by all helpers, but the installed filename/reference stem is `times`. |
| plus | Starter/title/details identify `+`; the arguments helper identifies reference page `plus`. |
| minus | Starter/title/details identify `-`; the arguments helper identifies reference page `minus`. |
| abs | Title uses a different single string from `abs`; details has a second numeric layout argument. Retain exact source-bound values rather than accepting arbitrary titles/layout arguments. |
| rminus | Symbolic `!-` and arguments-page `rminus` differ; details has a second numeric layout argument. |
| send, receive | Source starter text and saved filename use extensionless `helpstarter`. The dependency inventory names `helpstarter.js`; resolution to that verified file needs a finite policy. |
| div | Starter/title/details identify `/`; the arguments helper identifies reference page `div`. |
| modulo | All helper arguments consistently identify `%`; the installed filename/reference stem is `modulo`. |
| rdiv | Helpers identify `!/`; details has a second numeric layout argument, and the installed filename/reference stem is `rdiv`. |

**Reference and discovery routing.** None of the ten corresponding page IDs
is in `help_reference.rs`'s 13-entry reference catalog. Arithmetic needs an
explicit mapping between Max class and safe installed page ID: `+ -> plus`,
`* -> times`, `- -> minus`, `/ -> div`, `% -> modulo`, `!- -> rminus`,
`!/ -> rdiv`, and `abs -> abs`. A path containing the literal division class
must not be constructed by substituting that class into the current filename
template. Send/receive also need deliberate catalog entries. The existing
ordinary F1/library path opens original demos; recognition or a passing score
would not automatically route normal Help to an installed root.

**Saved policies and displays.** All ten still save font/editor/tab/loader
metadata that the generic importer diagnoses rather than resolving. Their
empty named-style collections do not erase font, grid/snap, toolbar, scrolling,
origin, inactive service or tab policies. Each arithmetic root has two to four
format6 flonums; reuse the four-root finite format6 disposition only where the
exact value/contract is the same. Modulo adds one float-output slider and three
saved horizontal orientations. No saved number/flonum minimum/maximum override
was found in the ten files, so arbitrary direct input remains limited by
Ultra's finite numeric profile rather than authored Max bounds.

**Runtime contract versus recognition.** The importer keeps a bounded-profile
warning on every modern scalar arithmetic node. `complete` requires every
diagnostic to be informational, independently of zero omissions. A finite
score/disposition can justify only its measured range and source-bound values;
adding native kinds or admitting helper shapes is not that score. The known
float `/` Infinity and float `%` NaN cases remain explicit local refusals.
The saved reverse-divide instances both have explicit creation operands, so
the unmeasured bare-`!/` default is not itself a blocker for this exact root.
Modern exponent creation is absent from all ten candidates and need not be
reopened to score them.

## Finite Behavior Work

Start with the three matching arithmetic topologies. Use small asymmetric
integer/fractional values, change each cold input without triggering, then
bang and check direct output tags plus display state. Restore and repeat the
same controls to establish retained state. Treat the arithmetic oracle as
object evidence and score the complete source tree through its actual anchors;
there is no need to capture another broad arithmetic method survey.

For abs, score signed slider paths and integer/float results. For reverse
operators, preserve the saved trigger's right-to-left sequence: its float
output updates the forward comparison object's cold operand, then its bang
output triggers a numeric Message which drives that same object's hot inlet.
The rdiv forward comparison object is created with a zero float divisor;
inspect the actual trigger path before claiming every action produces a
nonfinite result. Include an intentional zero case and recovery separately.
The div and modulo UI paths likewise need finite zero/refusal dispositions.

Send and receive each contain one unnamed, retargetable receiver and two fixed
named receivers; their `s`/`r` aliases form one of two fixed name pairs. Two
saved `set` Messages target the unnamed receiver, while another sends `set`
through the bus as data. The fixed names coincide between the two roots and
use neither `#0` nor `---` scoping. Test silent retargeting, delivery to only
currently bound receivers, typed payloads and cold Message display replacement.
Then open both independent owners and close one while repeating the other:
name collisions are part of the saved integration, not an isolated-root pass.
The existing native workspace test supplies retarget/data/close seams, but no
installed-root execution claim.

All ten still require complete source retention, exact helper recognition,
ordered runtime score, saved metadata disposition, shared view/owner lifecycle
and Save As/reopen checks before qualification. A Basic-only extraction or an
unconnected executable example must not disappear to improve a score.
