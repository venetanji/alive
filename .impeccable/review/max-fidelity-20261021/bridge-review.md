## Findings

### P2: Parameter admission originally used runtime-mutated bounds instead of the admitted authoring plan

Status: addressed; the scoped follow-up inspected the corrected source, original regression and recorded verification without execution.

The original runner copied `runtime.plan()` before calling `change_canvas_param`. Production admission instead copies `admitted_canvas[document]` in `apps/ultra/src-tauri/native/backend.cpp:549`. These plans can differ after a normal runtime message: the NumberInt/Flonum `min` and `max` handlers mutate the live plan in `apps/ultra/src-tauri/native/patch_graph.hpp:608`, without changing the authored parameter plan.

An original counterexample is a NumberInt authored with value 0, minimum 0 and maximum 100. Send `min -100` to inlet 0, then submit a cold parameter change setting maximum (slot 2) to -50. The old runner validated the candidate against the live minimum -100 and could accept it. Production admission validates against the authored minimum 0 and refuses the same change. The runtime bound guard at `apps/ultra/src-tauri/native/patch_graph.hpp:432` also permits the old runner's live minimum/maximum pair, so it did not recover the missing authored validation.

The fix maintains separate admitted plans at `apps/ultra/tests/help_root_runtime_test.cpp:236`, seeds them only after accepted installs at line 252, and validates authored edits against them at line 264. Accepted parameter updates advance that admitted plan; runtime messages continue to affect only runtime state. The optional hot trigger's return value no longer overwrites accepted parameter admission, matching the production idle backend's behavior at `apps/ultra/src-tauri/native/backend.cpp:558`; runtime failure and trace evidence remain separately available.

The nine-step original regression at `experiments/max-reference/help-roots-native-20261022/test-runner.py:47` covers both minimum/maximum divergence directions, refused edits, accepted edits advancing the admitted bounds, and reinstallation restoring authored bounds. The reviewer found no remaining instance of this admission defect in the scoped reread.

### P2: Generic transport validation originally refused valid MessageBox placeholder replacements

Status: addressed; the scoped follow-up inspected the corrected source, original regression and recorded verification without execution.

Production stores the template `original $1`; the old runner rejected the generic message during transport parsing and exited with code 10 instead of emitting a runtime receipt. The same problem applied to a valid hot `set original $1` replacement. The currently scored small rows for the four roots do not require these placeholders, but the old runner could not represent this supported production action.

The corrected bounded decoder at `apps/ultra/tests/help_root_runtime_test.cpp:155` checks capacity, hex/NUL encoding, atom tags and numeric validity, then delegates semantic syntax to the actual target/inlet admission via `workspace->event`.
