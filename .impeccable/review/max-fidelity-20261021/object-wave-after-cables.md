# Object Waves After The Four Small Roots

Read-only inventory and implementation recommendation, 2026-10-22. This pass
reads the current Ultra sources, retained experiments and licensed installed
JSON/XML. It starts no Max, Wine, Ultra, browser, DSP, build or test process and
copies no installed help prose, complete graphs, scripts or assets. The only
repository change is this report. Whole-help qualification remains **0/2,103**.

## Immediate Recommendation

After the current append/prepend/int/float work, score **inlet, outlet, plus,
times, send and receive** against their complete roots before adding an object.
They introduce no missing execution class in the present adapter vocabulary.
Then implement the six synchronous arithmetic primitives **`-`, `/`, `%`, `!-`,
`!/`, `abs`**, preserving lexical numeric configuration and observed message
types. These give six further small complete-root candidates without a timer,
new input widget, external abstraction or execution-capacity increase.

The next two coherent native batches are the **six comparison operators** and
**16 elementary scalar math objects**. Together with the arithmetic six and
the existing classes, they remove all missing class names from **38 core Max
roots**, compared with ten now. This is a candidate count, not 38 predicted
passes. Every root still needs helper admission, saved metadata/interaction
contracts, a runtime score and complete-root comparison.

Implement **loadbang/loadmess lifecycle** as the reusable parallel prerequisite,
then **split and simple umenu selection**, followed by **pak and switch**. These
are better early whole-root targets than delay, pipe, counter or gate. The
existing five-control recommendation remains useful for primitives, but by
itself `change/clip/gate/switch/split` removes all missing class names from only
one new root: split. The other four have additional real dependencies.

- Current `CanvasKind` has **54 native kinds**. `REGISTRY` has **56 authored

- Counts below use literal `box` namespace classes and object names. Embedded
  patchers recurse. `zl mode` is classified as `zl.mode`, avoiding the false
  conclusion that one existing zl implementation covers every mode. Aliases
  `i/f/s/r/t/sel` follow their existing adapter identities.
- Existing legacy Ultra `counter`, `makenote`, `midiin` and raw-linear `gain~`

  known incompatible contract. A zero missing-name count does not settle its
  semantics, creation arguments, attributes, initialization or messages.
- The four help-script families are removed from the *native-name* gap sets
  and tracked separately. That is an analytical partition, not permission to
  execute scripts or extend the current four-source shell allowlist.
- A hypothetical lowered-node count removes p containers, comments, the four
  helper families and explicitly identified disabled/unwired text annotations.
  It retains inlet/outlet relays and all other saved boxes, including isolated

Among the 472 core Max roots, ten have no missing native/UI class name, 115
have one, and 93 have two after the helper partition. A one-name gap can still
mean a new subsystem: coll, arrays, strings, host I/O and managed code are not
equivalent in effort to scalar arithmetic.

## Concrete Small-Root Closure

The current ten are append, prepend, int, float, inlet, outlet, plus, times,
send and receive. All ten have 4..16 hypothetical native nodes and 2..12
cables. A further resource template contains no missing class but is not an
object-help demonstration. None of these counts advances qualification.

None of the eight plus/times/arithmetic-six roots contains comma, semicolon,
message substitution or #0 syntax in its saved message boxes. This makes them
particularly useful next complete-root scores. It does not prove that their
other saved attributes are supported. Plus/times already need careful lexical
integer/float behavior; the existing bounded Add/Multiply implementation and
its import warnings are not an oracle for the new operators.

Class-only cumulative totals are **10 existing -> 16 with arithmetic -> 22
with comparisons -> 38 with elementary math**. Elementary math alone adds 16
small roots to the current ten. The proposed ordering gives common reusable
arithmetic before less frequent math objects; it is not a measured effort or
performance estimate.

## Helpers And Help UI Are Different Tracks

Actual saved script-box references identify helpstarter in **997** files,
helpname in **1,001**, helpdetails in **1,186** and helpargs in **483**. This
normalizes extensionless references such as `js helpstarter` to the installed
helper identity. The earlier report's dependency-cache counts
948/955/1,123/466 count declarations instead; these populations are different.
Only **42 roots** contain another js/jsui/v8/v8ui script identity, including
seven core Max and eight core MSP roots. This is not a count of all managed or
package dependencies: Node, mxj, RNBO and abstractions remain separate.

The send/receive roots use the extensionless helpstarter spelling. That needs
an explicit resolver/identity rule when expanding exact-source helper admission;
it does not justify generic JS execution or treating every `help*.js` as inert.
The current shell recognizes four roots, so the other six zero-name-gap roots
remain outside that finite source policy until deliberately added and scored.

Of **2,109 textbutton instances**, **2,038** have all three facts: ignoreclick=1,
no incident cable, and parameter_enable=0. **551 of 597 textbutton roots** have
only that subset; in core Max, 117 of 122 do. They can have an explicit
nonexecuting help-annotation contract that preserves text, hint, saved styles
and hit/tooltip behavior. They need no invented outlet execution. The remaining
71 instances require actual textbutton behavior, state, three ports and output
ordering. Source retention alone qualifies neither subset.

Attrui is more substantial: all 417 core Max instances save an `attr` field and
1-inlet/1-outlet shape. It needs a native attribute schema/query/update contract
for its connected target, editor state and silently versus actively changed
values. Parameter metadata, menu filtering and get-only attributes cannot be
implemented by dropping the box or forwarding an arbitrary number.

The simple menus in pak/switch/unpack have no saved autopopulate, prefix,
prefix_mode, menumode, valueof or saved-attribute record. Pak has **nine** saved
menu items, so an eight-item bound would immediately miss its intended root;
menu item capacity and eight-atom message capacity are different limits.
These small menu cases are a reasonable first explicit contract. Umenu's own
169-box help also exercises file/media and other objects, so that contract is
not whole umenu-help support.

## Prerequisite Graph And Capacity Gates

The compiled owner graph still admits **32 nodes / 64 cables**, including
relays. The v2 authoring envelope of 512 nodes / 1,024 edges, extra child views
and 16 document slots do not enlarge a single owner's execution graph. A
complete saved root cannot be split into separately owned runtimes merely to
fit its native limit without changing message order, globals and state.

Loadbang's 18-box root additionally contains one empty unconnected newobj with
saved 1-inlet/1-outlet metadata. A source-specific editable placeholder policy
can retain that authored state without inventing a live unknown object. Adding
loadbang alone does not explain that box. Loadmess's root has no such gap.

The dependency sequence is therefore:

1. Existing typed synchronous executor -> arithmetic six -> comparisons and
   elementary math; score complete small roots at every step.
2. Atomic graph creation/restoration/bus binding -> loadbang/loadmess -> scoped
   abstraction initialization -> bpatcher/patcherargs and limited pcontrol.
3. Simple umenu -> unpack; umenu + pak -> pak; umenu + switch -> switch.
   Incdec + change adds change. Pack waits for capacity expansion.
4. Compatible counter + umenu + radiogroup -> gate. Counter's own whole root
   also waits for capacity expansion.
5. Bounded native millisecond queues -> delay/pipe primitives; abstraction,
   transport, list/collection and capacity work still gate their full roots.

The presence of only bpatcher/thispatcher in many BEAP wrappers is not a
two-primitive shortcut to their DSP. Resolving their instances exposes the
actual package graphs. Likewise the **563 RNBO roots** need an RNBO execution
family, not merely an rnbo~ display object.

## Signal Follow-Up

The current general mono runtime is a useful foundation. Help completion is
still dominated by input/output and visual signal controls: ezdac~ occurs in
377 roots (235 core MSP), number~ in 127 (105), live.gain~ in 198 (100), scope~
in 60 (54) and meter~ in 39 (32). They are missing behaviors, not aliases for
Ultra's legacy gain/voice pipeline.

The smallest current MSP candidates are **div~** with ezdac~ plus its disabled
textbutton annotation (7 native nodes/7 cables), then **minus~** with selector~
as well (11/12), and **plus~** with ezdac~, number~ and scope~ (13/10). A family
of ezdac~/number~/scope~/live.gain~/meter~/attrui/textbutton removes all missing
names from only four core MSP roots: div~, ezdac~, flonum~ and plus~. It does
not complete the existing oscillator/envelope helps.

Cycle~ still needs buffer~/peek~/plot~, loadbang, arithmetic/trig and iteration
(at least 75 nodes/77 cables). Phasor~ includes MC, transport, buffers and
additional signal operators (at least 73/73). Line~ includes multislider,
random/scale/uzi/zl.group, monitors and comma messages (at least 45/34). These
are whole-root dependencies even where their Basic target already runs in an
original native fixture. An ezdac~ adapter also needs shared DSP on/off state
and channel routing; number~ is not just a label and scope~ is not an output
device. None should receive a no-op execution adapter to clear diagnostics.

observations or copies of installed graphs.

Collect timing separately from logger arrival. |

Existing `03-hot-cold` and `13-initialization` captures plus the hierarchy
reference give reusable setup and some baseline behavior. They do not contain
a Max oracle for these six arithmetic operators or the whole elementary/math
family. `14-scheduler` only establishes one bounded metro run, delay
stop/retrigger and pipe clear case; it cannot specify general scheduling.
The old JS collector loses numeric atom tags inside lists. The new scalar
fixtures avoid that ambiguity for arithmetic outputs; pak/pipe list typing
needs an explicit typed collection method rather than inference from JSON
number spellings.

Each eventual root manifest must distinguish complete original-file admission,
all tabs/dependencies, ordered native messages, visible interaction, restored
state and source-protected Save As/reopen. A native original fixture, retained
JSON source, partial Basic fragment or mocked IPC test is not a whole-help pass.

pack/route/counter, with explicit ABI and dispatch budgets. It is unnecessary
for arithmetic, comparison, elementary math, loadmess, split, pak, switch or
change's currently counted trees. The eight-atom, finite +/-100000 scalar and
127-byte text profiles remain independent limits even after node arrays grow.
