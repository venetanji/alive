# Installed Help Runtime Preparation Plan

**Goal:** Prepare an original harness for the complete installed append/prepend
Basic chains A1-A4/P1-P2, without launching Max during preparation.

**Architecture:** Read pinned installed sources and place exact pristine and
expendable working copies only in a new private directory outside the repo.
An original driver opens the working roots, matches Basic anchors using private
saved geometry, and adds leaf observers while retaining all original cables.
Private serialization supplies Message text checkpoints. Only metadata, hashes,
finite original stimuli and redacted receipts may enter this package.

**Tech Stack:** Python 3 standard library, original Max legacy JS, existing Wine
and Xvfb for the later separately authorized capture.

## Constraints

- Parent approved preparation and working-copy serialization; no Max/Wine launch
  occurs until the parent reviews the harness/run schema and authorizes it.
- Own this new package only. Completed evidence packages and product files stay
  closed. No screenshots, clipboard, installed help bodies/prose/helper scripts
  or raw source-owned demonstration strings enter the repo.
- Original executable cables and their saved order remain intact. Observers are
  leaf branches and never forward messages. Their callback order is recorded;
  it does not establish saved destination order.
- Source, pristine and initial working-copy SHA-256 values agree. Only the
  expendable working copy can be serialized. Installed/pristine digests and
  original/source preference snapshots are checked after capture.
- Scalar int/float tags are observed. Numeric atom subtypes inside JS lists
  remain `unknown-number`. Null Message JS readbacks never mean empty text.
- Programmatic, physical entry and physical drag actions have separate labels.
  A preparation-only artifact or API capability failure qualifies no row/root.
