# Bounded Help Follow-Up

Twenty installed core help files were read as JSON. A deliberately limited
research adapter constructed temporary partial graphs from each `p basic` tab
and sent those graphs to Ultra's production `validatePatch`. Twenty connected
target-containing fragments validate across the previous ten objects and
numeric `metro`. Four additional target fragments are isolated nodes. None is a
whole-help conversion or a runtime compatibility pass.

Six separate original Ultra patches execute in the production C++ graph core,
covering all ten existing batch objects plus the current bounded `metro` and
`counter`. These authored scenarios have 60 behavioral assertions. Eight
adapter boundary assertions verify refusals that a naive importer could hide.
The runner's `results.json` records every omission, boundary cable, port-count
difference, native observation and source hash.

No app was launched or restarted, no audio device was opened, and no installed
help file, browser flow, Rust preparation or Tauri IPC was executed. No new Max
reference execution or timing oracle was captured. No proprietary help graphs,
messages, object arguments, helper scripts or artwork are redistributed here.

## Evidence Boundaries

| Layer | Executed Result |
| --- | --- |
| Installed `.maxhelp` JSON reads | 20 files, 20 basic tabs inspected. |
| Direct production `.maxhelp` intake | 0 accepted; size or Max `patcher` schema refuses the documents. |
| Temporary partial graph validation | 20 components with cables plus 4 isolated target nodes accepted; 11 object names have a connected target fragment. |
| Extracted help-fragment runtime | 0 executed. |
| Original authored Ultra native scenarios | 6 execute with 60 behavioral assertions passing. |
| Adapter refusal assertions | 8 pass. |
| Browser / desktop / Rust preparation | Not executed by this follow-up. |
| Max runtime comparison | Not executed by this follow-up. |
| Whole installed help corpus execution | Remains 0/2103; this work adds no passes. |

The adapter only recognizes an explicit set of object and UI boxes. It reads
literal arguments through the production object-entry parser, maps a small UI
parameter allowlist, retains saved cable port indices, and lays out nodes at
neutral coordinates. Other boxes and crossing cables are recorded as omitted.
This creates an induced subgraph, not an importer. The whole basic tab is never
reported as converted. Number-box integer coercion and Tab output, message-box
editing and cold display storage, UI state, attributes, helper scripts, hierarchy
and named global sends remain limitations even when a component validates.

The native transport maps the original fixture documents to descriptors and
calls `compile_canvas` and `CanvasRuntime` directly. It does not call the Rust
document preparation or C ABI entry points. Snapshots contain each node's latest
runtime message, not a complete ordered emission trace. In particular, unpack
overwrites its last message while emitting its outlets; the final snapshot is
the leftmost output. The arithmetic scenario checks right-to-left behavior by
making the result depend on the cold operand arriving first.

Node and `g++` are required. The runner compiles its original native transport in
a temporary directory and removes it after execution. The original `.ultra`
patches also load through the regular canvas document format; operation scores
live in `fixtures/scenarios.json`. Their browser interaction and full app
execution are not certified here.
