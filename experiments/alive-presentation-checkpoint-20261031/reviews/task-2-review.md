### Important (Should Fix)

1. **A non-hot final value equal to the canonical baseline can leave DSP at an earlier preview.** `apps/ultra/src-tauri/src/document_parameter_gestures.rs:36` constructs the final parameter hint with `hot:false` for every non-hot parameter, regardless of whether the final value differs from the accepted preview. It then calls canonical admission while the comparison graph intentionally still contains the baseline. The existing early return at `apps/ultra/src-tauri/src/document_commands.rs:100` returns success when the final patch matches that comparison graph and the hint is cold. For example, begin a sustain gesture at 0.65, successfully preview 0.4, then commit 0.65 without a separate 0.65 preview. Admission skips the setter, removes the gesture, and reports canonical 0.65 while DSP remains at 0.4. Explicit cancellation correctly sends the baseline, but a changed final commit must also reconcile native state. Preserve the transient owner/token/target qualification and force the qualified setter when the final native value needs reconciliation, without marking a non-hot target hot or reinstalling the graph. Add a focused native regression for this baseline-return commit; the retained native test covers changed-final hot output and non-hot cancel, not this case.

2. **An Alive competing-base rejection permanently traps the mounted control in its stale gesture.** `apps/ultra/ui/canvas-presentation-hosts.mjs:63` correctly rejects an observed base change, but never revokes that gesture or provides a fresh baseline. On every rejection, `apps/ultra/ui/canvas-presentation-view.mjs:38` restores the same gesture ID. Subsequent deliberate edits therefore reuse its obsolete `latest` value and always fail. Reproduction through the real renderer and Alive adapter: begin at 1; preview 1.2; publish another owner's accepted 1.6; cancel; enter and commit a fresh 1.7. Output is `writes:[1.2]`, `acceptedBase:1.6`, two identical conflict errors, and `hasDraft:true`; 1.7 never dispatches. Navigation keeps this cached mount, so it does not provide recovery. Distinguish terminal ownership conflicts from retryable write failures: revoke the stale gesture without restoring its baseline, clear the renderer's corresponding gesture reference, retain any new numeric draft, and let a subsequent user gesture capture 1.6 as its baseline. Extend the current cancellation-conflict test to prove the next intentional edit succeeds.

3. **Text presentation items never refresh after their canonical text or appearance changes.** `apps/ultra/ui/canvas-presentation-view.mjs:17` resolves text/style once, appends the text element, and returns without adding a view refresher. Owner publication and `update()` only refresh registered views. A comment edit does not need to change executable revision or presentation JSON, so the Ultra panel's identity also remains unchanged (`apps/ultra/ui/canvas-device-panel.mjs:11`). A focused probe with the real controller, Ultra adapter, and renderer changed a version-2 comment from `Before` to `After`, then called both `host.publish()` and `view.update()`; output was `canonical:"After", rendered:"Before"`. Register a scoped text refresher that resolves the current authored text and validated appearance, including removing styles that were cleared. Cover comment/message text changes while the surface remains mounted.
