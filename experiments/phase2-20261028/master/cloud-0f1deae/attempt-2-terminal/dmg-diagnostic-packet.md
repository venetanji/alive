# Intel DMG failure: diagnostic packet

Attempt 2's observed failure is a busy detach, not a build timeout: on macOS 26.6.1 image 20260824.0517.1, the log shows the Ultra app built and signed, then DMG `disk20` mounted at `/Volumes/dmg.Jpwoef`, and three failed ejects. What held the device and whether it would recur are unknown. The process exited before Alive packaging and artifact collection. This evidence does not support a specific fix.

The repo pins `@tauri-apps/cli` 2.8.4 in `apps/ultra/scripts/tooling/package-lock.json`; release.py invokes that CLI with `app,dmg` for both products (`apps/ultra/scripts/release.py:349`, `:365`). The upstream `tauri-cli-v2.8.4` source tag resolves to commit `80eadb7387459639037e3a279c61c9631b1dafe7`; its CLI Cargo.lock and CLI Cargo.toml select `tauri-bundler` 2.6.1. The upstream files at that commit are `crates/tauri-bundler/src/bundle/macos/dmg/bundle_dmg` (Git blob `fee840034f1774edc89e80a35179c7ebcb4cbd9e`), `dmg/mod.rs` (blob `bbc59e505064288845fd27310beb4fa8a67a841f`), and `crates/tauri-bundler/Cargo.toml` (blob `171d38ab3fec622869d1c2b2d01a0675ba3e4c29`). This maps the pinned release source; the failed runner's generated script itself was not retained, so no direct byte comparison is available.

Bundler `dmg/mod.rs` writes its embedded script to the output directory immediately before executing it; editing an existing generated script before CLI invocation is therefore not a reliable injection seam. The upstream script already handles `hdiutil detach` exit 16 with a maximum of three attempts and sleeps 2 and 4 seconds between them; a non-16 error exits immediately. The log's three busy messages match this behavior. Additional retries or forced detach are unproven remediation and are not proposed.

A small future diagnostic change could add a macOS-only failure step immediately after the unsigned/ad-hoc package build in `.github/workflows/ultra-desktop.yml:98`. Gate it on `failure()`, macOS, and the specific build step's failure (give that step an ID); preserve the original failure and do not suppress or change package/signing behavior. Query `hdiutil info -plist` and identify mounted images whose backing file is within this checkout's target release bundle directory. For only those mount points, record bounded `mount`/volume information and a bounded `lsof` on the mount path, capturing command exit status and stderr, with a short hard timeout and best-effort handling. Report PID, process name and matching open paths only; avoid process environment, full command lines, unrelated mounts and image contents. Use a fixed small output size and deadline, and treat no surviving mount, permission denial, a timed-out `lsof`, or no open files as inconclusive. Retain diagnostic text through a failure-only upload-artifact step with a distinct name and short retention; never detach, kill processes, or force unmount. Scope to the unsigned/ad-hoc path so signed release secrets are not captured. A step after Tauri exits may be too late to observe a transient holder; it does not prove absence.

The injection and parser can be tested without a macOS runtime by feeding representative `hdiutil` plist fixtures and mocked command results into a helper, including path-with-spaces, unrelated image, missing mount, timeouts, output caps, and original failure propagation. Such tests validate filtering/control flow only; a real hosted macOS observation is necessary to validate platform commands and reproduce the contention.

GitHub's attempt-2 jobs endpoint carries successful jobs forward; a failed-job-only rerun would normally target the failed Intel matrix job rather than rerun successful package jobs, but cannot add diagnostics to the already executed workflow definition. Instrumentation requires a new committed workflow revision and an explicitly authorized bounded run; a dispatch normally runs the entire matrix unless a carefully scoped diagnostic entry point is added. A single Intel diagnostic job would provide diagnostic evidence only, not replace full-matrix qualification at a new SHA. The previous Intel job ran about 46.5 minutes, against a 90-minute limit; a comparable cold build can cost that time again, with no guarantee of reproduction. Keep existing app/DMG formats, signing, publication and target requirements intact; obtain a controller decision before any cloud mutation.
