# Cloud Arrangement rejection observation diagnosis

## Conclusion

The source establishes a stale-counter defect in the new Master snapshot path, and the retained CI evidence is consistent with that defect causing this failure. It does not independently record both numeric values read by the failing assertion, so the exact observed pair and causal reproduction remain unverified. The defect is not a reason to remove or weaken the original `before_rejected + 1` assertion.

## Smallest correction and remaining uncertainty

In `master_snapshot_wire`, after successfully validating the coherent publication, overlay `value.rejected` with `rejected_.load()` before returning it, matching `coherent_wire`. This retains coherent score/Master publication for callback-owned fields while treating the off-callback rejection counter as an independently current observation, as the existing API already does. Apply once in the shared template so V2 projection, V3 and V4 all receive it. Preserve the current counter assertion, refusal text, generation, preparation, history and final count assertions. Do not increase the timeout. If subsequent instrumentation shows a separate UI ordering race, address that separately with a condition-based observation while still asserting exact equality; current artifacts do not establish such a race.
