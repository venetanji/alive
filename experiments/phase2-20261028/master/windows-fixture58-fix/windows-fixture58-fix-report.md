## Evidence and design

The failed job's path-syntax error leaves the specific failing token and whether rustc started unknown. Context7's official PowerShell documentation (`/microsoftdocs/powershell-docs`, `reference/7.7/Microsoft.PowerShell.Core/About/about_Preference_Variables.md`) says Windows mode passes `cmd.exe` arguments using legacy behavior. Official Windows Server cmd documentation (`/microsoftdocs/windowsserverdocs`, `WindowsServerDocs/administration/windows-commands/cmd.md`) says `/s` with `/c` strips the first and last quotes, and `&&` executes its second command only when the first succeeds. This supports investigating argument delivery and the combined stages; it does not prove the job's cause.

No installed `pwsh` or `powershell` was found via `command -v` or `find /usr /opt -maxdepth 5 -iname 'pwsh*'`; `command -v wine` returns `/usr/bin/wine`. Wine alone cannot reproduce the PowerShell-to-cmd boundary; no Wine prefix or local native/build resource was used. No Windows runtime or PowerShell test was available, so no red/green execution, syntax verification by PowerShell, or runtime success is claimed.

The unchanged original command assignment and `& cmd.exe /d /s /c "`"$command`""` run first. On its failure, the harness logs the expanded command, original exit and native argument preference, then invokes `master_resolver_launcher_diagnostic.ps1`. The diagnostic feeds separately marked `vcvars` and identical rustc compilation commands to one `cmd.exe /d /q` process over stdin, reports the individual stage exits, overall cmd exit and probe existence. The same process preserves the environment established by vcvars. A 45-second stopwatch budget covers async stdin write, flush, and timed process wait. Standard output and error are inherited, avoiding redirected output pipes. If still running, `Process.Kill(true)` is requested on a task with a separate five-second wait; a pending or failed cleanup is reported without waiting indefinitely, and the original failure remains authoritative. A cleanup that times out is not proof that all descendants terminated. It skips rustc on vcvars failure. Even if diagnostic compilation succeeds, the original exception is rethrown with the original exit; the fixture cases do not run and no false green is possible. Diagnostic exceptions are logged without replacing that failure. The output is a candidate comparison, not evidence until run on Windows; stdin encoding, inherited output capture, process APIs, timeout and owned-tree cleanup, cmd processing, and paths require Windows verification. Reproduction is available through the existing Windows job when the original fails; no workflow change is included.
