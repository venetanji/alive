## Findings

1. **Medium — bounded UI scheduling does not specify how to preserve reset ordering.** `docs/contracts/alive-master-v1.md:112` simultaneously requires one replaceable unsent gain, ordered reset relative to sets, and no unbounded reset list, but gives no representation, saturation behavior, or coalescing rule. For example, while a request is in flight, the user may enter gain A, reset, gain B, and another reset; replacing the one unsent gain with B can move or erase the A operation across a reset, while retaining every barrier grows without bound. Under prolonged FULL/BUSY, different compliant implementations can execute different intent sequences or silently lose resets. Specify an explicit bounded state machine, including which unsent operations may be coalesced, whether resets act as barriers, behavior when its capacity is reached, feedback, and generation cancellation. Add a pressure witness with alternating sets/resets and assert exact admission order and overflow outcome.

2. **Medium — fixture checker accepts incorrect fixtures while reporting success.** `docs/contracts/alive-master-v1-fixtures/check.py:15` skips every IPC file; lines 23-27 check only the general shape/range of positive v5 files, and never check the intended gain encoded in a filename, legacy score version, or semantic structure of negative fixtures. Lines 18-22 accept any parsing failure for a duplicate-named file without asserting the duplicate's location/key, so an unrelated malformed or duplicate member can satisfy a named witness. In a scratch copy I replaced both `invalid-over.json` and `gain-4.json` with valid `gain-1.json`; the checker still printed `raw structure and duplicate scan verified`. This falls short of the brief's fixture identity and expected raw-structure validation, even though the README properly disclaims actual decoder testing. Assert each fixture's expected raw structure/value and failure category/location (including escaped-key equality), and validate the specified IPC examples independently; retain the distinction from prospective decoder tests.
