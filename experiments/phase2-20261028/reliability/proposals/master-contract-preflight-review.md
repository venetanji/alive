# Master contract preparation review

Scope: read-only review of the draft against application HEAD `5d45a432577086925d3d8b50a4356b076abeb36f`, spec sections 6/11, plan Tasks 6-8, relevant source and the resolver scratch source. This is preparation only; it freezes no contract and authorizes no consumer work. P2.0 acceptance and the listed implementation witnesses remain separate gates.

## Verdicts

- Spec: changes required before freeze. The draft captures the main saved-owner, DSP, persistence and capability requirements, but its stopped-I/O command contract and rollback serial handling leave required behavior or failure preservation unresolved.
- Quality: changes required before freeze. The retry protocol lacks a machine-readable refusal discriminator, and the promised coherent score publication conflicts with an existing post-read atomic override. The resolver proposal is plausible for Linux, with its explicitly stated platform and provenance gates still open; the scratch fixture is not production proof.

## Findings

1. **High: install can consume the last serial and make mandatory rollback impossible.** The draft requires a fresh serial both for candidate installation and rollback, and refusal before mutation at exhaustion (`master-contract-draft.md:75`, `:77`, `:79`). If only one serial remains, candidate installation can consume it after stopping/resetting the old configuration, then a later install failure leaves no serial for restoration. Current `Host::apply` can fail after reset while closing/installing roots or configuring (`apps/ultra/src-tauri/src/session/host.rs:183`), and rollback invokes it again (`:164`). This turns an otherwise recoverable failure into stopped audio, contrary to the preservation intent. **Fix:** before stopping, reserve enough serial capacity for candidate and possible rollback, or define another monotonic scheme that guarantees rollback admission; test near `u64::MAX` and ensure exhaustion refuses before retirement.

2. **High: ordinary quiescent set and reset are not fully specified.** The spec requires stopped-control acceptance with no frame advance for values whenever I/O is off (`docs/superpowers/specs/2026-10-28-phase2-live-max-design.md:162`), while the draft explicitly describes direct set only after configure (`master-contract-draft.md:75`) and describes set/reset admission only with I/O live (`:77`). A user can stop I/O without changing the project and then change gain or reset the latch. Existing stopped controls drain and publish synchronously (`apps/ultra/src-tauri/native/backend.cpp:472`, `:506`); stop itself drains the existing queue (`:512`). **Fix:** define both commands for any configured, fully quiescent owner: preserve FIFO ordering with already admitted commands, directly set current/target without advancing time, and publish reset/serial/frame immediately. Specify behavior while retirement is pending, and add stopped-I/O interaction and queued-before-stop witnesses.

3. **Medium: `Result` error text cannot reliably drive the specified retry policy.** The IPC contract exposes only an actionable Tauri error (`master-contract-draft.md:98`), yet the UI must retry FULL and stop on permanent or stale errors (`:105`). Native numeric error codes are lost unless the bridge gives clients a stable discriminator; parsing human-facing prose is brittle. **Fix:** define a structured rejection with a stable code such as `FULL`, `STALE_GENERATION`, `INVALID`, `UNSUPPORTED`, or `EXHAUSTED`, plus a message, while retaining failure-shaped IPC. Test transient FULL and permanent refusals through the actual bridge contract.

4. **Medium: the whole-score coherence promise overlooks an existing post-publication field.** The draft requires score and Master from one publication (`master-contract-draft.md:85`), but the current coherent reader replaces `result.rejected` with an independent atomic read after verifying the sequence (`apps/ultra/src-tauri/native/alive_session.hpp:362`, `:369`). Following the proposed extension without addressing this produces a score whose rejection count is not from the same sequence as Master. **Fix:** either include the rejected count in the combined sequence and avoid that override in combined getters, or explicitly narrow the coherence guarantee and identify the independently sampled field. Add a concurrent publication witness for the chosen semantics.

5. **Medium: unavailable-capability installation has contradictory instructions.** The draft permits legacy/unity operation when optional symbols are absent (`master-contract-draft.md:65`, `:75`), but then unconditionally says to call `master_set` after configure (`:75`). An old library has no such function. **Fix:** branch installation explicitly: use the existing unity path without any optional call when unavailable, and perform serialled initialization only when capability is present; define the unavailable snapshot's accepted serial accordingly. Exercise a real old/partial library through installation and snapshot, not just resolver lookup.

## Evidence and remaining gates

The v2 decoder currently parses to `Value` and then a typed `BTreeMap`, so duplicate parameter keys can be lost (`apps/ultra/src-tauri/src/session/persistence.rs:77`, `:83`); the draft's pre-scan directly addresses this. The v5 raw-score requirement, atomic save approach, wrapper/history separation, exact ramp formula and callback boundary clock are consistent with the specified direction. Existing Open resolves explicit draft and dirty choices before install (`apps/ultra/src-tauri/src/session/desktop.rs:479`); the draft correctly distinguishes those committed choices from unintended mutation.

The scratch `probe.rs` links an anchor, uses Linux `RTLD_NOLOAD`, checks anchor identity and verifies shared static state for its complete fixture. Its `reproduce.sh` rebuilds files, so it was inspected rather than executed in this read-only review. It does not test optional-symbol provenance, Windows or macOS; the draft already treats those as unresolved. Callback cost, actual C/Rust ABI and layout, native loader behavior, persistence, rollback, and rendered UI evidence are prospective and were not claimed passing here.
