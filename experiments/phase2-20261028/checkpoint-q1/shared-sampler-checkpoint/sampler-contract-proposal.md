# Task 9: shared process sampling contract

## Decision

Keep the existing `DesktopSustained` one-second sampler as the sole sustained `ProcessGroups` owner. Publish each actual, successfully logged background observation for legacy `process_sample()` consumers. Do not trigger additional `/proc` traversals on request. All legacy call sites, their order and output count remain unchanged, including startup after capture, every dwell iteration, each third-cycle boundary and the post-loop terminal sample. The separate non-sustained synchronous collector and editor-resources caller remain functional and unchanged in behavior.

This deliberately consolidates two streams into one truthful 1 Hz stream. The union contains fewer unique observations; legacy rows may reference the same observation and must be identified as such. This does not preserve the two collectors' combined unique coverage, and does not establish a cause or fix for the 41 callback-budget events.

## Publication, freshness and provenance

- `DesktopSustained` owns a condition and a latest immutable publication containing a monotonically increasing source ID, the original outer `sampling_started` and completion time, and all three unmodified group dictionaries. Make a private deep copy at publication and return another copy to the reader; no caller can mutate a later record. Continue the original deadline progression, one-second schedule, catch-up, checks and one sustained JSONL record per actual periodic sample; no new sampling or schedule changes are introduced.
- The worker samples outside both the condition and existing metadata lock. Construct the sustained row with its original timing, action, playing, coverage and group fields, plus a unique `source_id`. Write it under the existing metadata lock before publishing. Then atomically replace the latest publication and notify readers under the condition. A write failure must instead become a worker error, wake readers and fail health. `source_id` links each sustained record to legacy records; it is an additive harness-output field, with no app, production, ABI or native schema change.
- At each sustained `process_sample()` invocation, record monotonic `request_monotonic`. Accept the latest published observation only when `request_monotonic - sampling_started <= 2.0` seconds; if none exists or it is older, wait for the next periodic publication. An observation beginning after the request is also eligible. On wake, recompute against the *original* request time, check errors/stop first, and accept only a publication meeting the same rule. Do not substitute wall clock or relabel any group `monotonic`, `sample_start`, `sample_end`, duration, CPU or coverage field. The request-to-publication wait has a monotonic 5 second deadline, capped by remaining `MAX_WALL`; explicit timeout or wall-limit failure replaces any stale fallback. An observation may take time to complete: the freshness rule measures its start against request time, not its completion, so completion latency remains visible and is bounded by the wait deadline.
- Legacy rows preserve the exact existing flattening: all app group fields at top level, and unchanged `sampler_capture_overhead` and `private_audio_server` dictionaries. Add a nested provenance object containing the shared `source_id`, request monotonic time, actual outer `sampling_started`, completion time, and signed `age_at_request_seconds = request_monotonic - sampling_started`. A negative age truthfully means the accepted observation began after the request; it must not be clamped or called an earlier observation. The same source ID can appear in several legacy records, with their own request times and ages. Matching source ID and group payloads establish precise equivalence to the sustained row; individual group timestamps retain their own actual values.
- Each call writes exactly one `resource-samples.jsonl` row and returns that same payload for `process_tree_samples`; a failed wait or write produces no successful entry. Construct the legacy `JsonLines` writer lazily even when no legacy collector is created. Serialize its write with the existing metadata lock so aggregate cap checks and sustained writes stay coherent. Never hold the condition while acquiring the metadata lock, during a write, or during `/proc` work. Preserve the metadata cap and report all errors rather than suppressing a row.

## Lifecycle and limits

Worker errors, including process/identity caps, wall checks and JSONL writes, are latched with their original cause and notify waiting readers. Stop marks the condition stopped and notifies all; waiters fail explicitly, and `health()` checks still expose the sampler error and recorder failure. `stop_sampling()` retains the existing bounded join and reports a stuck thread; cleanup must propagate failures that arise during stop/join, not lose them because an earlier health check succeeded. Do not hold either lock while joining. Normal retirement, epoch qualification, stopping the sampler, verified Quit and manifest order remain unchanged; cleanup still restores hooks and aggregates failures.

`ProcessGroups`, `ProcessSampler`, the per-group and union process/identity caps, CPU tracking, discovery coverage, missing/available field handling and source timestamps remain untouched. Since tracking now starts at sustained install and includes every periodic sample, legacy CPU deltas, retained identities, coverage gaps and lifetime-cap behavior reflect this one shared history instead of the former independently sampled history. Limits can therefore trigger at different times; no synthetic interval reconstruction is allowed. A sample exceeding the 2-second freshness bound or worker stalls can now cause a bounded failure. Metadata gains provenance fields and may hit its existing cap earlier. The change leaves recorder supervision, native monotonic clock, all actions/assertions, 180-second dwell, playing credits and gaps, epoch/retirement rules, hard caps, and forecast's 10% variability and 5% headroom unchanged.

## Concrete implementation and GI-free test packet

Three-file core packet:

1. `apps/ultra/tests/desktop_sustained.py`: add publication state, condition, monotonic source IDs and a bounded consumer method; publish only after successful sustained JSONL write; notify on failure and stop; preserve periodic loop and lifecycle. Inject or patch clock/wait seams for deterministic tests, not a generic collector framework.
2. `apps/ultra/tests/check_alive_desktop.py`: branch `process_sample()` on `sustained_driver`; consume and flatten the publication with explicit provenance, lazily create the legacy writer, and serialize its write. Retain the current independent `ProcessSampler`/`ProcessGroups` path when there is no sustained driver and retain all call sites.
3. `apps/ultra/tests/test_desktop_sustained_integration.py`: add deterministic GI-free publication/consumer/lifecycle tests using fake clock, controlled publication and temporary JSONL; place cross-file flattening logic in an importable GI-free seam if importing the full desktop driver requires GI. Existing `test_stream_measurement.py` cap, identity and coverage tests and `test_desktop_checkpoint.py` lifecycle tests remain part of the packet; add narrowly targeted assertions there only if the existing ones cannot exercise the invariant.

Required red tests, with no desktop/audio/real `/proc`:

- Publish a real fake periodic observation, consume it immediately and just inside the 2-second bound, and assert unchanged app/group fields, nested timestamps, source ID, request time and signed age. Two requests may return one source ID; each writes its own legacy record. At just over 2 seconds, prove the stale row cannot return: block until a later periodic publication, then check exact payload equivalence, signed age, and no extra collector invocation.
- Check no initial publication and an in-flight sample; advance the fake clock across 5 seconds and `MAX_WALL` and verify timeout or wall failure without a legacy row. Test wakeup for a later observation, stop, collection error, sustained write failure, metadata limit and legacy write failure, preserving causes and avoiding deadlocks. Test that publication occurs only after the sustained write and returned mutation cannot affect stored data or another reader.
- Verify scheduled timestamps, one-second deadline progression, missed cadence, overdue catch-up and one sustained row per actual periodic sample, including while a UI action blocks. Verify sampler failure during shutdown, join timeout, restored hooks, retirement/qualification before stop and Quit, and health failure. Existing process and identity union cap, PID reuse, unavailable and coverage-gap tests must continue to pass; add a fake shared-history case demonstrating truthful deltas and retained cap enforcement across publications.
- Exercise startup, repeated dwell, boundary and terminal call positions through a GI-free seam or focused source-level structure checks; verify every successful call yields one legacy JSONL row and report entry without altering actions or observation calls. Test the independent editor path still creates synchronous groups and yields the same fields and assertions when `sustained_driver` is absent. No live run is authorized by this contract.
