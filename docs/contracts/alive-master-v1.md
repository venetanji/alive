## Saved owner, history, migration

Authoritative owner (names, fields and ownership normative):


Accessors may minimize call-site churn but must not duplicate mutable score or Master owners. `prepare(&SavedSession, path)` validates Master and prepares `saved.score`, carrying the whole wrapper into PreparedSession; all v3/v4 conversions and structural edits clone current wrapper, replacing only score. `Host::base/mixer/bypass` mutate `saved.score`; `alive_master` mutates `saved.master` only after native admission succeeds. Draft materialization and `merge_live` work on score alone, then wrap with current master's metadata; Apply, Discard, Undo, Redo and structure changes never overwrite it. `Host::install` retains previous complete PreparedSession on failure; candidate Open/New has its own wrapper, never assigned to current until native install succeeds. Save As rebases device paths in a candidate score, wraps the unchanged Master, serializes, and commits path/rebased score/wire/dirty only after atomic rename. Existing code to adapt: `session/prepare.rs:29`, `session/host.rs:160`, `session/desktop.rs:9`, `:173`, `:190`, `:217`, `:427`, `:472`, `session/history.rs:19`, `session/persistence.rs:7` (all under `apps/ultra/src-tauri/src`).

Wire exactly `{ "format":"alive-session-v5", "score": <one v2/v3/v4 score>, "master":{"gain":number} }`; required fields, no extras; finite gain in [0,4]. A single recursive duplicate-key scan of the entire original UTF-8 text must precede ANY `Value` or typed parse, including v2 parameter maps, v1 legacy files and outer/nested objects. Then use a deny-unknown envelope containing `Box<RawValue>` score, inspect the raw score's format and invoke the relevant strict decoder from original bytes; explicitly reject v1 and v5 inside the envelope. Preserve existing bare v1 migration and bare v2/v3/v4 support; v1 migrates to its existing v2/v3 behavior. Current v2 `BTreeMap` generic decode silently replaces duplicate parameter keys (`session/persistence.rs:93`, `session/mod.rs:55`); v3 and v4 already have recursive scanners (`session/clips.rs:163`, `session/workspaces.rs:273`). Reuse/generalize scanner, not an intermediate `Value` and not generic `Document` Deserialize. Bound raw complete file at <=1,048,576 bytes before decode and serialized bytes including final newline before write.

Bare old file loads Master=1, `LegacyScore`; new session starts 1, `V5`; v5 loads `V5` even at unity. An accepted actual gain change, including subsequent return to unity, permanently promotes `LegacyScore` to `V5` for that in-memory project; a no-op gain equal to accepted target does not promote or dirty. Clip reset never promotes or dirties. After promotion a save writes v5, even after resetting to unity; successful first migrated save reports `Saved in Alive session v5 format` in visible save feedback; V5 stays V5 on reopen. An old unity score without a gain change retains its current bare score wire on save, subject to the existing v1/v2-to-v3 explicit conversion notice; preserve that conversion rather than pretending its original score version survived. Dirty is set on accepted changed gain even if it returns to saved value, consistent with existing sticky `Control.dirty`; failed/refused/no-op requests, cancelled file chooser/dialog, failed serialization/rename leave wire, owner, path, dirty and history intact. This is separate from score draft resolution. Do not mark clean until rename succeeds.

## Installation, live commands and clock

Prevalidate capability and saved gain before stopping/replacing the old configuration; if capability is absent, allow unity operation with unavailable UI, but reject installing non-unity v5 with actionable error before replacement. Branch explicitly after configure: with full capability, initialize using `master_set(1, saved_gain, candidate_serial)` while `!running && !engine.status().ready` and configured, setting current=target, zero ramp and publishing serial at unchanged absolute frame before I/O starts. With absent/partial capability, unity installation uses only existing reset/configure APIs, makes **no** optional call, and exposes `available=false`, `acceptedSerial="0"`, null observation and actionable reason. This branch also applies to unity v5; it retains v5 on save. Reset/configure discard the old queue and clear Master peaks/latch where capability exists. A non-unity owner cannot be installed or silently coerced to unity in this branch.

Before stopping or retiring I/O, and before any native replacement, reserve **two** consecutive nonzero process-lifetime serials atomically while holding the Control lock: candidate and rollback. If fewer than two remain, return EXHAUSTED without stopping I/O or mutating owner, native state, generation, history or dirty state. Reservation advances the allocator immediately; never reuse either serial even if validation or candidate succeeds and rollback serial is unused. Reserve the pair for every capable install, including when no previous project exists, for one uniform exhaustion rule. No other ingress may interleave between reservation and candidate/rollback completion. Use candidate serial only if candidate reaches initialization. `Driver::stop` initiates retirement and can return `retirement_pending` while the callback still owns native resources (`audio.rs:328`, `:348`); if stop fails or remains pending before replacement begins, burn both reserved serials, return that existing result, and do not call native reset, configure, candidate initialization or rollback. The prior owner, generation, accepted serial, score and draft remain intact; I/O retirement has nevertheless been initiated and is reaped normally, so do not claim playback is unchanged. Retry installation only after the existing quiescence check succeeds, with a newly reserved pair. Once stop has succeeded and native replacement has begun, if a candidate step fails, reapply the previous complete PreparedSession and initialize its previous *accepted saved target* with the reserved rollback serial directly before restarting I/O. On successful rollback, record the rollback install serial as the retained generation’s `acceptedSerial`, so it agrees with the newly published applied receipt; preserve its saved gain, wire, dirty state, score and history. If rollback fails, do not claim the reserved rollback serial as accepted; report restoration failure. This preserves strict ordering even if candidate fails before its own serial is applied. `Host::apply` can fail after reset (`session/host.rs:175`); reservation guarantees serial exhaustion cannot cause rollback failure. Other native restoration failures still surface explicitly and leave the saved owner in memory with audio stopped. Never restore a partial old ramp. A missing-capability unity install consumes no Master serials and performs no optional rollback call; its old-state rollback uses the existing native unity path. Driver stop is observable; preflight and validate before retiring it.

With I/O live, including transport stopped, set/reset enters the existing 65-slot ring (64 usable); both `begin` and `begin_v3` handle the two kinds, FIFO order. With a configured fully quiescent owner (`!running && !engine.status().ready`) and no retirement in progress, first synchronously drain all earlier admitted ring commands in FIFO order via the stopped-control reducer, then process the new set or reset in that same order and publish before returning. A quiescent set sets current=target immediately with no ramp; reset clears only latch. Both publish their own serial and unchanged absolute frame, with no generated samples or clock advance. Draining previously admitted Master set/reset during stop uses the quiescent rule and their original order; no later direct command may bypass them. A stopped stream with a retiring callback/device owner is not quiescent: reject both commands with structured BUSY before serial/native/saved-state mutation; callers can retry after retirement completes. The Control lock and existing driver retirement checks serialize the transition so a producer cannot race the callback or stopped drain (`native/backend.cpp:472`, `:506`, `:512`).

Rust validates document generation while holding Control lock and allocates a process-lifetime strictly increasing nonzero u64 serial for each admitted command. Refuse before mutation on exhaustion; never wrap/reuse; represent as decimal strings in IPC. Only advance the accepted serial on success; a failed attempt may leave a gap if allocation precedes native enqueue. Queue full, invalid, unsupported, busy and stale generation do not alter saved gain or promote wire. No heap, locks or unbounded queue on callback; charge worst-case 64 commands and per-frame DSP/publication work to every v3/v4 admission envelope, remeasure all admitted profiles and existing deadline guards. Stop's out-of-band epoch must remain processed first under saturation; neither set nor latch reset can invalidate it. Reset/configure discard old queued Master commands; Rust generation check rejects delayed IPC from old project even where IDs coincide.

At callback boundary, `applied_frame` is the absolute index of the next sample, before `advance` increments it (`alive_session.hpp:347`); quiescent commands report the unchanged next-frame index. For new set at boundary use current coefficient as `from`, `k=0..63`, gain `from + (target-from)*(k+1)/64`, exact target thereafter; command during a ramp starts from last rendered coefficient, including multiple FIFO commands at one boundary (last target governs next sample, all are applied in FIFO). No ramp on initial/quiescent set. Reset command updates applied serial/frame and clears latch at its FIFO position; later samples may immediately relatch. Latest applied serial is monotonic and acknowledges all prior admitted Master operations in that generation; pending status is inferred by serial comparison, not by target equality. Installation has its own serial and resets latch, not musical time. Serial must remain monotonic across generation and rollback.

## Concrete Task 6 seam and ownership boundaries

`decode(text, origin) -> SavedSession` performs the raw scan and format dispatch; `prepare(saved: &SavedSession, path) -> PreparedSession` clones that complete wrapper into the prepared result.
