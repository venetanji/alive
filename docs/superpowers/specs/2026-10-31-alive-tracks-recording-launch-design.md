# MIDI/Audio Tracks, Quantized Launch And Live Recording

Date: 2026-10-31. Status: proposed design for user review, not implemented.
Source checkpoint: `4dfc7be` on draft PR #6.
Revised after the Live input-routing/arm study in
`docs/ALIVE_INPUT_ROUTING_REFERENCE.md`. Observed behavior, manual findings and
Alive scope choices are distinguished there.

## 1. Requested Outcome And Delivery Order

The user wants explicit creation of MIDI and audio tracks, different clips that
launch with quantization, and live microphone/audio-interface recording in the
current development scope. Recording is included; WAV import alone is not the
requested end state.

Use the existing native engine, transport, effects, mixer and Master. Deliver
three independently testable stages, with a focused implementation plan and
review for each:

1. Configurable clip launching and visible queued/playing state on existing MIDI
   tracks, preserving old projects' one-bar behavior.
2. Explicit typed track creation, empty MIDI instrument slots, real WAV playback
   and mixed MIDI/audio projects. Prove a small mixed fixture before measuring
   the target eight-track workspace profile.
3. Global input configuration, independent per-track routing/monitoring/arm,
   live input recording into empty Session audio slots, immediate record-to-loop
   transition and recoverable background finalization while other tracks
   continue. Recorded sources can also be placed in Arrangement.

This order includes recording in the work, while giving it proven playback and
asset ownership to build on. Each stage needs its own implementation plan; this
document is the shared architecture and delivery boundary. Direct recording
onto the Arrangement timeline, overdub/punch, internal audio taps, Resampling,
physical MIDI ingress and multiple simultaneous captured takes are later
extensions. Multiple armed tracks and independent monitoring are included;
arming must not be redefined to mean owning the single capture reservation.

The accepted 2026-10-26 runtime/desktop contracts and 2026-10-28 Phase 2 design
remain authoritative for ownership, PCM format, source identity, history and
file safety except for the explicit additive changes here. Q1 and the retained
native failures remain open; feature progress does not complete qualification.

## 2. Approaches And Recommendation

| Approach | Consequence |
| --- | --- |
| Extend the current native host in the three stages above | Recommended. Both track types share timing and audio processing; each new runtime capability has a measurable gate. |
| Add audio-looking tracks and recording controls before native support | Does not satisfy the request: current preparation rejects audio, and output callbacks alone do not capture an input. |
| Replace the audio/UI stack or add a separate browser audio engine | Splits ownership, reopens device/clock problems and discards working native integration. |

Keep Rust/Tauri and CPAL 0.18.2. No decoder dependency or framework migration is
required by this design. The strict, bounded PCM RIFF subset already specified
can be decoded locally and tested against generated byte fixtures.

## 3. User Workflow And Track Types

Expose Insert MIDI Track and Insert Audio Track as explicit commands in both
workspaces. Show track type in the header and the applicable controls in detail.
Browser activation loads an instrument into the selected empty MIDI track, or
creates a MIDI track when the user explicitly chooses Add Track. Selection
alone still has no musical effect.

- A new MIDI track has four empty Session slots and an empty instrument slot.
  It accepts MIDI clips and note editing immediately. It produces no audio until
  an instrument is loaded; the detail panel explains this and offers the real
  bundled instrument. An unassigned track is not represented by a fake device.
- A new audio track has four empty Session slots and no instrument slot. It
  accepts compatible WAV clips and, in stage 3, Audio From/channel selectors,
  record arm and Monitor In/Auto/Off. It never accepts MIDI note content.
- An instrument's stereo output and an audio source feed the same ordered
  stereo effects, track gain/mute/solo/meters and saved Master. Both participate
  in the same scenes, Arrangement authority and per-track Return behavior.
- Clip/source identity is same-track and type-checked. Moving or copying a clip
  between unlike track types refuses with an explanation; rendering MIDI to
  audio and automatic kind conversion are outside this design.

Track creation/removal and device structure remain stopped operations. Refuse
before opening a picker or changing the document if the current native track,
root or work capacity would be exceeded. Creation/removal is one owner
transaction; cancellation/refusal preserves document, history and preparation.

The target workspace capacity is eight tracks, sixteen total device roots,
at most two effects per track and four Session slots per track. These are target
ceilings, not existing admission. Start with an actual MIDI+audio two-track
proof; enable larger mixed profiles only after native envelope, deadline and
rollback measurements. Show the effective admitted limit in the UI. Do not
advertise eight tracks by unlocking profile 2's reserved storage alone.

## 4. Launch Quantization

Put a Launch Quantization selector in the musical toolbar, defaulting to 1 Bar.
Each occupied Session clip has Global or an explicit override in clip detail.
The fixed project meter remains 4/4 for this slice.

| Label | Period in quarter-note beats |
| --- | --- |
| None | Immediate at the next native control-consumption frame |
| 1/32 | 0.125 |
| 1/16 | 0.25 |
| 1/8 | 0.5 |
| 1/4 | 1 |
| 1/2 | 2 |
| 1 Bar | 4 |
| 2 Bars | 8 |
| 4 Bars | 16 |
| 8 Bars | 32 |

Use finite serialized enum values `none`, `thirtySecond`, `sixteenth`, `eighth`,
`quarter`, `half`, `bar1`, `bar2`, `bar4`, `bar8`; clip overrides additionally
accept `global`. No free-form floating-point grid enters the native request.

Resolve the effective grid when a launch is accepted. The native owner selects
the earliest reachable boundary at or after its current position, including
the current frame if already on that boundary. This preserves the actual
existing `target_frame` behavior; it does not invent an extra bar of delay.
Compute frame boundaries from beat origin and tempo, with existing checked
rounding. Do not repeatedly add a rounded period and accumulate drift.

The song/loop-entry seams remain boundaries as in the existing workspace
contract. A target beyond a nonlooping song end produces a terminal canceled
receipt. None still uses the native queue and safety/admission rules. Stopped
launches cue at phase zero without starting transport.

An individual launch uses its clip override or Global. Track Stop and Return
use Global. A scene uses one captured Global grid for every member, including
empty-slot Stops, so it stays atomic. Global musical Stop remains immediate
and uses the reserved mailbox. Changing the selector affects future requests;
it never silently retimes a request already queued.

Display selected, queued, playing and stopped as distinct states using native
receipts. A queued clip can be replaced by another launch on that track; retain
the original replacement/cancellation receipt. Navigation does not launch.
Show the effective grid and target in detail/accessible status without making
browser animation the clock.

Add a versioned native quantized-request boundary and explicit capability.
Preserve old ABI field meanings, reserved-field rejection and default behavior.
Recompute quantization/seam work envelopes for every admitted grid, including
short loops containing an internal grid boundary. The old prepared 65-bar array
and six-boundary proof cannot simply be reused for finer grids. Denied work
leaves the existing playback and receipt state coherent.

## 5. Saved Format And Compatibility

Do not add permissive optional fields to strict v2/v3/v4/v5 wire decoders.
Introduce an explicit `alive-session-v6` envelope containing `score`, `master`
and `launch`. It can retain an existing strict score unchanged for stage 1.

`launch` contains `globalQuantization` and a bounded list `clipQuantization` of
`{ occurrenceId, quantization }` overrides. Each occurrence ID must resolve to
an owned Session clip/slot; duplicate, missing or cross-document targets reject.
Omitted overrides mean Global. Copy copies the override to the new occurrence;
delete removes it; Undo restores both exact IDs and metadata. Queued requests
keep their captured grid when these settings change.

For stage 2 add a distinct strict workspace score format
`alive-workspaces-v1`, retaining v4 source/slot/placement fields and identity
rules, with `chain.kind=midi` allowing a required nullable `instrument` field.
`chain.kind=audio` has no instrument field. Old v4 MIDI chains keep their
mandatory instrument contract. Instrumentless MIDI preparation omits note
dispatch and owns no instrument root while retaining the actual authored notes
in the document. Effect-only and all-empty projects must still configure and
reach the normal mixer/Master path.

Legacy loads default to 1 Bar/Global. Preserve their original wire until a new
feature requires v6; never silently drop Master, clips, sources or launch
settings to save an older format. Keep duplicate-member rejection, unknown-field
rejection, the 1 MiB document limit and 64-entry/8 MiB history limits. Launch
setting edits are saved owner transactions without a transport reset or device
rebuild. Preparation revisions and desktop generations fence all commands.

Stage 3 introduces a strict `alive-session-v7` envelope with required `score`,
`master`, `launch` and `routing` members; it does not mutate the v6 decoder.
`routing` uses an explicit version and exactly one entry per owned track ID.
Audio entries contain a tagged No Input or Ext. In source, a mono channel or
stereo pair for Ext. In, Monitor In/Auto/Off and the supported Main
destination. MIDI entries remain No Input with unavailable external ingress;
their output is No Output without an instrument or Main after an instrument.
Reject duplicate/foreign track IDs, unknown route tags, incompatible kinds and
structurally invalid channel pairs. Channel numbers are 1-based in 1..32;
stereo pairs are consecutive odd/even channels. A saved route whose channels
are absent or disabled on this machine remains identifiable but unavailable;
loading never substitutes other channels.
Track create/delete/Undo maintain the routing entries in the same transaction.

Hardware device/channel enables and Exclusive Arm are machine preferences,
outside project files. Arm, capture reservations and input-enable state are
transient. Persist monitor intent, but opening a project starts its input gate
disabled and all tracks unarmed, even if the audio output engine already runs.
An explicit Enable Inputs action enables effective monitoring for that project.
Legacy projects acquire audio Off/MIDI Auto and No Input when upgraded; a new
audio track uses Ext. In mono 1 only when that configured channel exists,
otherwise No Input. Input availability is never inferred from a saved label.

## 6. Real Audio Assets And Playback

Implement the accepted 48 kHz mono/stereo signed PCM16/24 RIFF subset, with the
exact malformed-header, length, format, fingerprint and path checks in section 5
of the earlier runtime contract. Limit each source file to 2,880,000 frames
(60 seconds) and 24 MiB encoded bytes; at most eight distinct decoded buffers
and 64 MiB prepared PCM per generation. Keep current-plus-candidate unique PCM
within 128 MiB. Display these bounds in import/recording help and refuse early.

Decode/hash/create peaks off callback into immutable pinned owners. Draw actual
decoded min/max peaks, at most 4096 bins per source, and request bounded windows
instead of attaching every waveform to polling snapshots. Mono duplicates to
stereo; stereo preserves channels. Source offsets and suffix loops use exact
PCM frames; tempo does not change sample rate or pitch. Warp/resampling is a
separate extension.

Audit zero-instrument routing, optional instrument dereferences, device role
checks, render/clear/chase, mixer/Master and retirement on every affected path.
Do not use `canvas.any()` or instrument presence as the audio-only render guard.
Prove source reads and output with known impulses/ramp fixtures through the real
effect/mixer/Master chain before exposing audio import as a working capability.

Relocate preserves source ID and requires identical content/descriptor. Replace
creates a new source ID and atomically rewires explicitly selected readers;
other readers keep the old source. Validate every offset/duration before commit.
Save As rebases audio/devices/history. Collect And Save is a separate atomic
operation with collision checks and rollback; ordinary Save leaves external
assets external. Never overwrite an audio/device dependency with a project.

## 7. Recording And Monitoring

### Hardware Configuration And Per-Track Routing

The first recorder captures one audio take at a time, mono or stereo at 48 kHz,
into an empty Session slot. This is an Alive capture-capacity limit, not a limit
of one armed track or one monitored route. Other MIDI and audio tracks continue.

Global Audio Settings select actual compatible input hardware and enable its
mono channels/stereo pairs. Keep output configuration and input configuration
distinct. Support at most 32 hardware input channels on the verified backend;
only enabled channel choices appear on tracks. Changing hardware/channel enables
is an explicit stopped-engine operation, unavailable during a take/finalization.
Do not ask a track to select its own physical device. Missing/disconnected
hardware remains identifiable and offers Configure; it is never auto-replaced.

Each audio track owns Audio From (Ext. In or No Input), a channel/pair chooser,
Monitor In/Auto/Off and Audio To Main. Configure opens the global input settings.
The source/channel does not change when selection, arm or another track changes.
Several tracks may monitor the same channel, or different channels, through
their own effects and mixers. Unsupported internal tracks, Resampling, hardware
output routing and routing taps are absent from selectable menus until their
typed native graph, ordering and feedback rules exist. Their presence in Live
is documented in the reference; it is not a capability claim for this slice.

MIDI clips remain editable/launchable without physical MIDI ingress. Do not
render functioning-looking All Ins, port, channel or MIDI-arm controls before
an actual MIDI input owner exists. Show No Input and the unavailable capability
in MIDI track detail. External MIDI capture is a separate extension; inserting
an instrument does not claim Live's automatic MIDI-arm behavior in this slice.

### Arm, Monitor And Playback Are Independent

Track state includes selected identity, saved route/monitor intent, runtime arm,
effective input availability, current clip authority and recording phase. Both
workspaces read the same native owner. UI polling does not drive these states.

Exclusive Arm defaults on. Ordinary audio-arm clicks arm/select the target and
disarm the other audio tracks; Ctrl-click on Linux preserves their arm states.
With Exclusive Arm off, an ordinary click toggles only its target. Never change
any input route as a side effect. Clicking an already armed target disarms it;
Ctrl-click toggles its arm without changing the others. Multi-selection arming
is not exposed until
track multi-selection itself exists. No Input or unavailable hardware prevents
recording and shows why; capacity refusal occurs on Record, not on Arm.

| Monitor | Effective input through effects/mixer | Clip output | Armed capture |
| --- | --- | --- | --- |
| In | Enabled regardless of arm | Suppressed | Allowed |
| Auto | Enabled only when armed and no clip is playing | Playing clip is heard; it inhibits live input monitoring | Allowed |
| Off | Disabled | Normal playback | Allowed |

The project input gate and device availability qualify every input-enabled row.
No Input supplies silence. Auto consults actual native clip playback in Session
or Arrangement, not selection or a queued launch. Recording a new slot replaces
the previous clip's authority at the admitted recording boundary. Capture reads
raw selected input before effects/gain regardless of Monitor. Monitor edits do
not change recorded samples. An In track can have a logically playing clip with
suppressed audio; show this reason rather than falsely reporting audible output.

Monitor In continues with musical transport stopped while the audio engine and
project input gate run. Musical Stop ends clips/capture; Stop Audio ends input
monitoring too. Add an explicit native monitor path through effects/mixer/Master
when transport is stopped. Projects with no effective monitor retain stopped
silence. Meter input activity separately from clip/track output; overload and
missing-input status do not depend on the Arm button's color.

### Recording Actions And State Transitions

An armed empty audio slot exposes a circular Record action. The Session Record
control targets the selected scene's slot on every armed audio track. With more
than one armed target, refuse the entire request with the one-take capacity
reason before transport, clips, arm, routing or files change. An occupied target
refuses without overwriting it. This first Session Record eligibility policy is
an Alive scope choice; exact Live occupied-slot interactions remain unverified.
With no armed audio target, show Arm an Audio Track and make no musical change.

Reserve track/slot, source handle, PCM, file, history and receipt capacity before
accepting a recording request. An unavailable route or unresolved clock mapping
refuses early. From stopped transport, accepted Record starts at phase zero;
while playing, capture starts at the earliest reachable captured Global grid.
Normal scene launch does not record empty armed slots. Start Recording on Scene
Launch is not offered in the first recorder. Session Record is explicitly named;
do not connect an Arrangement Record-looking button to Session capture.

| State/action | Native result and UI feedback |
| --- | --- |
| Armed, no Record action | No sample capture; empty slots offer Record. |
| Record accepted | Reserve one take and show queued recording with its target boundary. |
| Queued recording, Session Record again | Cancel the queued start and release the reservation; this is the first-recorder cancel policy. |
| Native start receipt | Capture begins in the reserved slot; show recording and elapsed take time. |
| Recording clip Launch, or Session Record again | Queue the recording-to-loop cut at the captured Global grid. |
| Native cut receipt | Seal the exact take prefix and start its loop at that boundary; disk finalization may remain pending. |
| Clip Stop | End capture at its captured Global boundary and retain the take stopped. |
| Transport Stop | End capture immediately and retain the take stopped; no automatic loop or later transport restart. |
| Disarm before queued start | Cancel the queued take and release its reservation. |
| Disarm during capture, including Exclusive Arm changing track | End capture at the next native control boundary and retain it stopped; apply arm changes in that same transaction. This is the explicit Alive policy pending an equivalent Live runtime study. |
| 60-second limit or nonlooping song end | End capture, retain it stopped and explain the cause; only song end ends transport. |
| Input fault/overflow | End the take with an error and retain its verified contiguous prefix for recovery. |

Arm, queued recording, actual recording, looping playback and finalization must
have distinct text/accessible states as well as visual treatment. Finalization
is an independent durability status: a looping take may still be finalizing.
Recording-to-loop is a required completed workflow, not a promise inferred from
the ability to import the file later. Other tracks and their queued actions
continue through every normal recording transition.

### Bounded Input And Take Ownership

Use one preallocated 131072-frame interleaved input ring for the enabled
multichannel bus, consumed once by the native output owner. Independent track
routes read that frame before passing it through each track's chain; they do
not compete to pop the ring. At 32 `f32` channels the ring is 16 MiB. The single
selected recording stream uses a separate 131072-frame stereo worker ring
(1 MiB maximum). The earlier two-stereo-ring/2 MiB design does not support this
independent routing model and is superseded.

Reserve a complete 60-second mono/stereo take buffer before recording, at most
2,880,000 x 2 x 4 = 23,040,000 bytes. The native owner writes quantized capture
values into it and the worker stream; at record-to-loop it seals the prefix for
immutable playback without waiting for a WAV header or disk sync. The exact
safe source-handle/length publication is a new native capability, not a reuse
of stopped-only Apply. These buffers and both rings count with current and
candidate unique PCM against a 128 MiB recording ownership budget. Refuse a
take before allocation if that full reservation does not fit. Existing per-file
and 64 MiB per-prepared-generation limits still apply; transfer a sealed take's
ownership without double-counting shared memory.

Input/output callbacks allocate, lock, decode, destroy and write files zero
times. A worker drains the selected capture ring, encodes PCM24, builds peaks
and tracks durable progress. Quantize finite input with defined rounding and
saturation; playback uses those same quantized values. File bytes and playback
must agree. Count overloads and reject nonfinite recorded samples. Input ring
overflow/loss/timestamp discontinuity or worker-ring overflow ends capture with
an explicit error; never silently insert samples into a successful take.
Monitor underflow outputs silence with its own counter. Any missing captured
interval is a take fault, even if the monitoring path can continue.

### Clock Mapping Is A Required First Probe

Pinned CPAL 0.18.2 explicitly says StreamInstant origins are not guaranteed to
be shared across streams. Do not subtract input and output timestamps merely
because both report 48 kHz, or use JavaScript arrival time as capture position.

Prove a mapping from capture samples to the native output-frame clock on the
chosen Linux backend before implementing the recorder interface. Begin with
input/output on a verified shared device/server clock. Record timestamp anchors,
actual callback partitions, declared latency/offset and drift. Test separate
origins, discontinuities, late input, ring boundaries and callback retirement.
Refuse unsupported independent-clock pairs rather than silently resample.
If the current CPAL backend cannot establish the mapping, a common-clock duplex
adapter is a prerequisite, with a concrete probe result before changing APIs.

Software fixtures must select exactly the intended input frames and reproduce
them at the declared transport offset under arbitrary callback partitions.
Physical loopback measurements separately report alignment, latency and drift
for the tested interface; software success is not hardware qualification.

Prove that all input frames selected for a recording-to-loop cut are available
by its native publication boundary under the declared buffering/latency policy.
The sealed prefix must not require future input, discard a tail silently or
insert a gap. Declare the applied capture offset in diagnostics; the first
recorder has one measured alignment policy and does not advertise Live's Keep
Monitoring Latency setting. A finalizing-then-launching prototype can validate
files/publication, but does not pass the immediate-loop completion condition.

### Finalization, Recovery And Live Activation

Record into uniquely created temporary assets plus a bounded journal. Only the
worker writes/syncs files or updates durable progress. On finish, validate the
frame count, close/finalize the WAV header, sync, fingerprint and atomically
promote the file. Expose pending/finalizing durability until the asset is ready,
separately from native loop playback or stopped state.
Crash recovery offers the verified, complete-frame prefix recorded in the
durable journal. Recovery never overwrites an unrelated file.

The current stopped-only Prepare/Apply path cannot attach a new recorded source
while playback continues. Stage 3 needs two explicit operations. Before capture,
admit a reserved runtime take/source/slot handle with pinned writable storage and
bounded transition metadata. At the cut, seal its written frame range and
activate immutable playback through that pre-admitted handle, using only a
bounded native owner action. Track/device structure does not change. Stopping
instead seals it without launching. This requires a versioned capability and
new native proofs; a frontend promise or implicit global Stop/Apply cannot do it.

After durable finalization, validate the canonical source descriptor and its
fingerprint off callback. Commit document/history and publish the successor
mapping without restarting or shifting the already playing take. Keep the
reserved PCM pinned until the canonical source is acknowledged and stale
requests retire. Use the same immutable buffer where valid. Publication must
preserve queues and original receipts on unaffected tracks; index changes
cannot retarget them. Reject failures without disturbing their playback.
Attaching the durable source and slot is one history entry. Undo does not delete
the WAV required for Redo. Transient take identity and pending durability are
visible until this commit; ordinary Save waits for the take to become durable.

Failed finalization leaves the in-memory take and verified temporary prefix
recoverable, with Retry, Keep Partial and Discard actions. It is never labeled
saved. Discard first stops any transient playback and obtains retirement
acknowledgement before releasing memory/files. Quit waits for safe finalization
or an explicit keep/discard decision, never silently losing a take. Finalization
does not restart a stopped transport. Crash recovery preserves only journaled
complete frames; it does not promise recovery of unflushed in-memory playback.
Open/New and structural edits refuse while capture/finalization owns the track;
the message names the active take and how to finish or cancel it. They cannot
replace the generation underneath the capture worker.
Begin recording requires an applied project with no pending authoring edits.
Authoring transactions wait until capture/finalization finishes in this first
recorder; live mixer controls and launching other tracks remain available.
Tempo and seek/loop-region edits wait too, keeping the captured time-to-frame
mapping and recorded clip length stable. This is an explicit first-recorder
restriction, not a Live compatibility claim.
Launching a different clip on the recording track first requires finishing or
stopping the take; its own recording-slot Launch is the record-to-loop action.
Input route edits on that track wait too; Monitor changes and independent
arm/disarm remain live under the transitions above. Another take is refused
until the previous take's finalization releases its capture reservation.

### I/O Strip And Responsive Layout

Use the existing charcoal, Liberation Sans, original icons, 112-180px Session
columns and fixed-right Master. Put a global I/O visibility toggle in View,
with a keyboard shortcut that works outside text editing. Hiding I/O never
changes route/monitor/arm. Keep Arm reachable beside Solo in the mixer even
when I/O is hidden. Use a red arm indicator and a separate monitoring indication
with accessible labels; do not use red to mean both armed and actively capturing.

In Session, the I/O block sits between clip slots and the existing mixer:
Audio From, source chooser, channel chooser, Monitor In/Auto/Off, then Audio To
Main. Choosers fill the column; each occupies its own row. Do not squeeze source
and channel into one ambiguous field. For MIDI, show the truthful unavailable
input/output state described above. Main is a fixed destination in this slice,
so render a value rather than a nonfunctional routing menu. Keep slot/scene
rows aligned independently of track type and I/O visibility.

In Arrangement, place the same controls alongside the existing right-side
track controls. Collapsed lanes retain arm and a concise input summary; unfold
or the selected-track detail reveals the full I/O block. View switches preserve
route, arm, effective monitoring, current recording and focused drafts.

At 1440x900 and 1280x800, show expanded I/O on visible track columns and unfolded
Arrangement tracks. At 1024x768 and 800x600, retain readable control sizes and
regional scrolling: tracks scroll horizontally while Master remains anchored;
the I/O/mixer region can scroll vertically without moving transport or hiding
its record/stop actions. The browser can collapse and detail can be resized or
hidden, restoring the user's requested sizes when space returns. Reduce optional
labels/diagnostics before essential controls. Do not scale the whole app with
CSS transforms or shrink controls until labels collide. Below the native
minimum, the browser preview may expose only one selected track at a time with
regional scrolling; native capture remains capability-gated.

Channel menus stay within the available viewport, scroll internally and support
keyboard selection. Show full route names through focus/hover help when clipped.
Input meters identify signal/overload even before arm. Missing inputs and
capture-capacity refusals have inline text near the responsible control and a
reachable Configure action. New UI validation must include changing view and
window size while a track is armed, monitoring, queued, recording and looping
with pending finalization; resizing itself sends no musical command.

## 8. Validation And Completion Conditions

- Launch: independent frame oracle for every grid, boundary equality, tempo
  extremes, irregular loops, nonlooping end, scene atomicity, repeated requests,
  cancellation, seek, Stop and unchanged old ABI behavior. Check actual PCM/event
  onset and native receipts under different callback partitions.
- Tracks/assets: empty MIDI, instrument assignment/removal, audio-only zero-root
  and mixed projects, real channel values/offset/looping, kind refusals, early
  capacity refusal, stale generations and complete rollback/history equality.
- Recording: deterministic private input graph, known sample content, arm and
  exclusive/modifier multi-arm without route mutation, all monitor modes with
  playing/stopped clips, Session Record atomic capacity refusal, quantized
  start/record-to-loop and immediate Stop, independent loop/durability state,
  input disappearance, overflow, disk full, failed finalize/publication,
  crash-prefix recovery and actual Quit/restart. Check the cut/first-loop PCM
  without a disk-finalization gap and preserve unaffected queued receipts.
- Persistence: new and legacy wire round trips, malformed/foreign/duplicate
  metadata, shared/independent readers, Save As and collected project relocation
  with original assets hidden. Reopen/play compares state and PCM.
- Native admission: measure the complete mixed/recording envelope and rerun
  affected MIDI profiles after shared changes. Reserved storage is not a pass.
- UI: keyboard access, focused drafts, both workspaces at 1440x900, 1280x800,
  1024x768 and 800x600, long source names, absent input, menu bounds, regional
  scrolling and visible record/Stop/Master during live resize. Existing
  Node/Rust/Chromium suites and relevant native journeys remain regression gates.

Each stage reports its actual supported capabilities, measurements and failures.
The overall request is complete only when distinct new MIDI/audio tracks,
configurable launching and actual input recording are available in a rebuilt,
tested app. A schema, button, waveform thumbnail or plan alone does not meet it.
