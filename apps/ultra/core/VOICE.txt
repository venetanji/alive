Application Faust voice and native bus contract
=============================================

The legacy fixed Voice object uses voice.dsp -> generated/app_voice.hpp, class
UltraAppVoice. It no
longer imports experiments/faust-reference/host.hpp in production. That original
fixed-envelope fixture and experiments/clockwork-faust remain unchanged oracles.

The two logical instruments each own four prepared AOT Faust voices. Attack event
kind 6 and release kind 7 accept MIDI-sized values 0..127. Value zero means the
original 16 frames (one third of a millisecond at 48kHz). Nonzero values mean
attack value*192 frames (4ms) and release value*384 frames (8ms), up to 508ms
attack and 1016ms release. The generated oscillator, gain and level arithmetic is
unchanged; at the default timings, the existing hardened oracle scores remain
bit-exact after the existing 64-frame causal adapter delay.

Attack/release edits update instrument defaults and idle voices' prepared zones.
Both parameters latch at note-on. Held notes, sustained notes and already-running
release tails retain their own timings; edits affect the next note, including a
stolen/retriggered voice. Level remains live. The reset event immediately clears
voices and restores level=1, sustain off and both 16-frame envelope defaults.
All-off releases held/sustained notes using their latched envelope. Repeated
all-off does not extend a release. Internal HardClear kind 8 is distinct: it
immediately clears every voice and sustain while preserving level/attack/release,
for route disconnects and sequence-ownership changes. Native app-facing ingress
must not expose that internal kind. This prevents a long release tail from
reappearing if a removed route reconnects before its musical release finishes.
This is linear Faust ASR: note-off during attack
starts its release slope at the attained amplitude, and therefore ends sooner
than the nominal full-scale release time. Host voice retirement matches the
generated float slope, including the final zero sample, rather than hard-coding
16 frames. Timings map exactly to the integer frame parameters above; Faust's
single-precision reciprocal may leave a one-ULP endpoint residual for some
values (for example 41), requiring one extra sample to reach full scale/zero.
Retirement follows that actual DSP endpoint and does not cut off the residual.
An earlier-silent voice can consequently become reusable sooner than
the old fixed-envelope host's conservative lifetime.

All tables, MapUI maps and DSP instances are created/initialized before callback
exposure and destroyed only after the callback stops. Event handlers only update
fixed state/prepared zones; no compiler, dynamic voice creation or zone lookup is
used in the callback.

AudioBusView is an explicit planar channel bundle at the Engine boundary.
render_bus currently requires exactly two non-null output buffers. This exposes
the native bus capability instead of making left/right parameters the only
interface, but does not implement arbitrary widths, spatial/ambisonic processing
or downmixing. Unsupported/null buses stick the engine in fail-closed state
without dereferencing an invalid-width channel array or writing unknown memory.
The next valid render is silent until stopped shutdown+init. Existing render and
C APIs retain their two-channel compatibility signatures.

Reproduce
---------
Prerequisite: the existing pinned experiments/faust-reference dependency setup.
From repository root:
  python3 apps/ultra/core/generate_voice.py

The generator calls official libfaust generateCAuxFilesFromFile with:
  -lang cpp -cn UltraAppVoice
  -I experiments/faust-reference/.deps/faust-2.88.0/libraries
  -o apps/ultra/core/generated/app_voice.hpp

Compiler: Faust 2.88.0, Linux x86_64 libfaust release. Existing setup.sh verifies:
  faust-2.88.0.tar.gz
    e4e175cf236924b5b7d4784cbb8c50cc01e211159e169655dd9e6d8f92b871d9
  libfaust-ubuntu-x86_64.zip
    7f7784567d8770dfbc1351f53b32dfb4d4c5baef0ba5f39fd925d5407ab63ff2
The checked-in generated header retains compiler flags, author, library version
and license metadata. Regeneration normalizes trailing horizontal whitespace only.

Build and run the real-Clockwork application envelope/bus suite:
  D="$PWD/experiments/clockwork-faust/.deps"
  export PATH="$D/cmake-3.31.6-linux-x86_64/bin:$D/rust/bin:$PATH"
  export CARGO_HOME="$D/cargo"
  cmake -S apps/ultra/core -B /tmp/ultra-envelope-build \
    -DULTRA_BUILD_CORE_TESTS=ON -DCMAKE_BUILD_TYPE=Release
  cmake --build /tmp/ultra-envelope-build --target check_ultra_envelope -j4
  ctest --test-dir /tmp/ultra-envelope-build --output-on-failure

Authored four-voice canvas instrument
------------------------------------
The authored instrument is a separate graph profile within the existing native
canvas evaluator. Its six primitives are PolyNote (60, poly.note~), SawVoice (61,
saw.voice~), FilterVoice (62, lowpass.voice~), AdsrVoice (63, adsr.voice~),
MultiplyVoice (64, *.voice~), and MixVoice (65, mix.voice~). The graph's cables
connect these operations; the engine contains no hidden fixed subtractive route.
The example multiplies the oscillator/filter result by envelope and velocity,
then reduces the four lanes through mix.voice~ before gain~/join~/stereo.dac~.

Native port type 5 and the Voices dependency domain describe exactly four
discrete voice lanes, including when the allocator's structural capacity is
1..3. They never implicitly connect to mono, stereo, control, or transparent
mono/control relay ports. Every compiled signal edge records its exact width.
MixVoice explicitly sums the four lanes and divides by four for headroom. Public
native audio output remains mono/stereo; voice lanes are not speaker channels.
Partial authoring graphs can omit PolyNote and remain silent. One allocator is
allowed per document, and every node/lane's DSP and MIDI state is independent.

PolyNote receives [MIDI pitch, velocity] on inlet 0 and sustain 0..127 on inlet 1.
Its outlets are frequency in Hz, gate 0/1, and normalized velocity 0..1. Velocity
zero releases the oldest still-held matching pitch. Sustain values >=64 hold
released keys until a value <64 arrives. Notes have no lease while held or
sustained. Allocation uses the oldest voice when every configured slot is busy;
stealing clears that lane's prepared kernels before retriggering. Repeated note
offs do not extend release. Each release snapshots the maximum authored ADSR
release duration in that document (1..10000ms); the lane retires no later than
that deadline even if live edits subsequently lengthen the release parameter.
Disconnected or shorter envelopes can become silent before this conservative
retirement deadline. Panic on inlet 0, document Stop, graph replacement, close,
global Stop, and stopped audio teardown immediately clear allocator/DSP state.

FilterVoice's scalar inlets 1/2 and live parameters p0/p1 are cutoff 20..20000Hz
and Q 0.1..20. AdsrVoice's scalar inlets 1..4 and p0..p3 are attack/decay/release
1..10000ms and sustain 0..1. Their defaults are 2400Hz/Q0.7 and
10ms/150ms/0.65/300ms. All ADSR parameters stay live, in contrast to the legacy
Voice object's latched ASR. Unsupported creation fields remain zero; capacity
changes require structural graph replacement.

voice_saw.dsp, voice_filter.dsp and voice_adsr.dsp import the pinned Faust 2.88.0
stdlib's os.sawtooth (saw2), fi.resonlp and en.adsr. Regenerate with:
  python3 apps/ultra/core/generate_voice_kernels.py
The generated voice_*.hpp files retain exact compiler flags, function/library
versions, author and license metadata. Their signal-only interfaces require no
MapUI or compiler in the host. The private minimal architecture in
native/canvas_voice_objects.hpp is project-owned and supplies only the generated
empty UI/metadata interfaces. No upstream architecture header is modified.
Each document prepares its fixed per-node/per-lane kernel storage before callback
exposure; render performs bounded clears, parameter/input writes and compute(1).
It performs no allocation, DSP initialization, ownership destruction or locking.

The new kernels execute in CanvasRuntime::signal_sample on the native host
timeline alongside the retained Clockwork guest. They are not hosted inside that
guest and do not acquire its 64-frame causal voice delay. The existing startup
and graph-install silence guard remains. The guest and native path still share
the engine's callback/clock/fault boundary. Full-queue noteoff, sustain-release
and panic use an out-of-band Stop mailbox. A bounded control-thread walk follows
authored control cables and static Send/Receive names across all 16 admitted
documents, each limited to 32 nodes. An unnamed, runtime-rebindable Receive is
conservatively treated as a possible match for every Send. The walk ignores
message transforms: a rejected bang into a stored release message can therefore
request Stop even though its original payload does not identify a note-off.

Every document with a modeled control path to an affected Voice/PolyNote is
stopped, including related producers and timer sources. Their epochs discard
older accepted FIFO actions, so a queued note-on from another sender cannot
rearm the target. A grouped atomic mailbox reasserts the complete Stop group if
the callback observed only part of its epoch updates. Documents without a
modeled path keep running. This is conservative termination of related roots;
it does not attempt to evaluate the rejected authored message. Release-shaped
messages report accepted safety termination; unclassified messages still report
rejection after requesting Stop. Direct gate-on and sustain-on messages reject
without this fallback. A later newly accepted note can start a document again.
Int/Float's dynamic `send <name>` method is outside this route inference; its
overload ingress rejection does not provide the modeled-path Stop guarantee.
