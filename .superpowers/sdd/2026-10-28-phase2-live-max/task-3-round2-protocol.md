# Owner Save Preflight (working design)

Each owner has at most one pending Save request in `Registry`; a monotonic token and a bounded set of ready linked views fence acknowledgements. The initiating native Save snapshots only after all members acknowledge. Each editor uses its existing synchronous draft capture and queue drain via an independent `save/<owner>` local barrier. A failed editor rejects the whole Save, keeps the draft and focus, and causes all participant barriers to be released. A capacity-one wake channel wakes a blocking worker; no UI or audio callback waits. A bounded timeout refuses a missing acknowledgement.

Registration of a newly ready view adds it to an outstanding preflight while holding the registry lock; the snapshot is taken under that same lock only after the waiting set is empty. A disappearing member fails the preflight; stale, duplicated, wrong-owner and wrong-token replies fail validation. Concurrent Save for the same owner refuses; unrelated owners remain independent. A release event is fenced in the UI so a late event or late flush cannot acknowledge or reactivate an obsolete barrier. Close/Quit barriers use separate keys, so Save after an existing close flush can drain an empty queue and release only its Save barrier. Save increments the existing Quit `saves` counter while preflight and picker are pending.

The native owner snapshot is captured atomically under the registry mutex before releasing Save barriers and before displaying a picker. Subsequent edits may proceed during the picker/write; existing `registry.saved` compares the saved snapshot to the then-current document and retains dirty state. Failure, timeout, picker cancellation and delivery failure release all Save barriers. The owner-close protocol remains separate and unchanged. Tests need exact red/green for invalid peer and both view directions, delayed peer commit and preflight acknowledgement, stale/disappearing/newly ready peers, post-flush edits during picker, close-then-Save, and OS-window close.

Review follow-up: an owner reservation survives preflight removal and remains until picker/write success, cancellation, error or worker failure. Barrier reconciliation polls the native token/membership state once per second while an editor holds a Save barrier; if a release event is lost, the editor releases once the preflight no longer exists. Only one timer per active owner/view is retained and disposal cancels timers; IPC errors retry without granting an unsafe release. The last pending Save schedules the still-current fenced Quit generation after failure/cancellation handling, so an unrelated in-flight Save cannot consume Quit's only wake.

The reservation, Quit save counter and emergency barrier release are owned by a worker-side RAII lease. They are cleaned up even if the asynchronous command future is dropped or the blocking worker unwinds; the lease schedules a still-current Quit generation only after handling cancellation. `document_save_flushed` logs an acknowledgement only after validation succeeds, so stale responses are not reported as accepted.
