## Collector Lifetime And Results

Create one request-owned collector per installation, preferably as a closure
passed through the existing validation path. It persists across the existing
polls, unlike the per-pass diagnostic arrays. It can wait for the first fully
eligible pass under unchanged settling limits. Latch attempted before the
first capability access; at most three ordered format/getvalue pairs may be
attempted for this request. No later poll retries a partially completed batch,
reuses it to admit an object, or substitutes it for a fresh observation.

For each ordered numeric target, call only getattr('format') followed by
getvalueof(), using the classified status/representation schema specified below.
Preserve unavailable, throwing, null, undefined, ambiguous-array, other and
nonfinite outcomes. Never turn an unavailable or refused probe into a value.
Retain every completed method result before checking later currentness or
propagating an error. Verify source/config/command/owner/root, complete retained
host bindings and target identity before and after each call, including after
the final host property read. A mutation suppresses subsequent calls and
preserves partial evidence with an explicit invalidated disposition.

Publish a separate optional private ACK diagnostic envelope for this exact
minus request. It contains an immutable plain-data source/request/owner
binding, ordered per-target observations, count/status and any currentness
refusal. It must not expose live host handles. Keep evidence from its actual
collection pass separate from later per-pass diagnostics. Subsequent polls,
exceptions and terminal fail() must not erase, relabel, or replace it. Export
must preserve collected results if later host reads throw. Existing ACK
fields remain intact. The seven-case requirement applies to collection
eligibility and unchanged fixtures. Terminal diagnostic arrays always describe
the actual terminal validation pass, including new/missing/changed count,
traversal, binding, class or geometry failures. Never copy collection-pass
diagnostics back into those arrays or force them to contain seven rows. Mark
the separate collection stale monotonically on any later checked invalidation,
without rewriting its binding, completed results or first collection failure.
Do not change
failure-latch, ACK/journal write or reader semantics for other requests.

### Safe Operations And Finite Guards

Keep the existing times/plus capability helper isolated. Its two method-property
lookups are unsuitable for this collector. For minus, perform one guarded
property lookup per method slot. Latch the batch before the first lookup,
record the lookup outcome, run the currentness guard after lookup and before
invocation, then invoke that captured function with its original object receiver.
Never perform a second method-property lookup or inspect an untrusted function's
call/apply/toString properties. Capture a trusted bound intrinsic apply bridge
before target probing; if the host lacks a safe bridge, record unsupported
invocation and stop. Initialization of this optional bridge must not break
times/plus startup. A call that throws through the bridge is an actual invocation
throw, with no fallback or retry.

Each guard is one finite ordered sample of the complete captured host bindings:
root/child association and ownership, ordered scope inventories, object wrappers,
names/classes/rectangles, then root filepath last. Compare this sample to the
retained eligible bindings. After the final host read, finish with exact plain-
data command/shared-action/definition/configuration/owner snapshot comparisons;
perform no further host read in that guard. Run a guard before lookup, after
lookup/before invocation and after outcome classification, including after the
last method. A throwing guard fails closed, retains earlier evidence and stops
subsequent lookups/invocations. No loop seeks a stable sample and no atomic or
simultaneous host snapshot is claimed. A property change outside these finite
observations remains unobserved; include this limit in later evidence audit.

Increment invocation_attempts immediately before calling the bridge. On return
or throw, set the plain method record's invocation status and retain the outcome
in the closure before any classification or guard that could throw. Never
serialize an arbitrary returned host object or call its conversion methods.
Classification may read a returned array's length and sole element once each;
if those reads throw, preserve invocation_status=returned with representation
classification-threw and stop the batch. A later guard failure cannot relabel
a returned method as an invocation throw. The raw reference may be held only
inside the closure while classifying; it must never enter ACK export.

Stable unavailable methods and lookup/invocation throws are diagnostic outcomes:
if the post-operation guard passes, continue to the next ordered slot. A failed
guard, unsafe bridge or classification exception stops all later slots. Preserve
all completed records and the first stopping reason; no later poll retries the
batch. An outcome returning another value shape is classified and may continue
if currentness passes; it does not establish any numeric/default/mode agreement.

### Exact Private ACK Contract

The optional new key is minus_numeric_preflight_diagnostic. It is absent if no
fully eligible batch ever starts, and required once the first lookup begins.
All other ACK keys keep their existing schemas and meanings. The envelope has
exactly these keys:

- version: the string minus-controller-diagnostic-v1.
- binding: exactly command, owner, working_path, source_projection_sha256,
  helper_sha256, command_snapshot_sha256, definition_snapshot_sha256,
  configuration_snapshot_sha256 and owner_snapshot_sha256. command is an
  immutable plain copy of the exact eight-key command101 operation. owner is
  the exact seven-key configured owner4 record. The four snapshot digests bind
  canonical plain data captured at eligibility; shared action identity is
  checked directly against command. No live handles are included.
- collection: exactly poll_index, diagnostic_sha256, status and first_failure.
  poll_index is the existing positive install-attempt index. diagnostic_sha256
  binds the eligible pass's exact seven diagnostic rows. status is complete
  or stopped, fixed at the end of that batch. first_failure is null for a
  complete batch, otherwise the exact three-key record stage, method_index,
  code. method_index is zero-based0..5; stage is guard-before-lookup, lookup,
  guard-before-invocation, invocation, classification or guard-after-outcome.
  code is a code-owned string describing the stopping condition, never an
  arbitrary exception/host conversion. The first failure never changes.
- methods: exactly six records, in target order root/obj-2/obj-1,
  root/obj-2/obj-24, root/obj-2/obj-23, each with getattr/format then getvalueof.
  Each record has exactly anchor, method, attribute, lookup_status,
  invocation_status and observation. attribute is format for getattr, null for
  getvalueof. lookup_status is unattempted, callable, unavailable or threw.
  invocation_status is unattempted, returned, threw or unsupported. Untouched
  trailing slots have both statuses unattempted and observation null.
- counts: exactly lookups_attempted, invocation_attempts,
  invocation_outcomes_retained and completed_pairs, all nonnegative integers.
- terminal_context: exactly stale and first_invalidation. stale starts false
  and can only become true. first_invalidation starts null and, on the first
  checked collection-time or later invalidation, becomes exactly poll_index,
  stage and code. stage is collection-guard, later-validation or terminal-guard.
  Preserve this first record and all immutable collection data thereafter.

For a lookup throw, lookup_status=threw, invocation_status=unattempted and
observation=null. For an unavailable lookup, invocation_status=unattempted
and observation is method/status=unavailable/representation=unavailable/value=null
(plus attribute=format for getattr). For a callable method whose bridge cannot
be safely used, invocation_status=unsupported and observation=null. No invocation
was attempted in any of these three cases.

An actual invocation throw has observation with method, status=threw,
representation=threw and value=null (plus attribute for getattr). A return uses
status=returned and representation scalar-number, singleton-number-array, null,
undefined, ambiguous-array, other, nonfinite or classification-threw. Only the
two finite numeric representations carry their actual numeric value; all other
representations carry value=null. This classified schema intentionally omits
arbitrary raw object content, ambiguous array contents, nonnumeric values and
exception payloads. It is not a lossless raw return encoding, a receipt-tag
observation, or evidence of scalar/default/mode agreement. Classification-threw
records that the invocation returned but its bounded classification failed.

lookups_attempted counts every non-unattempted lookup slot, including throws;
invocation_attempts counts bridge calls; invocation_outcomes_retained counts
returned/threw invocation records and must equal invocation_attempts, including
classification-threw outcomes. completed_pairs counts contiguous target pairs
whose two slots finish guarded processing (including stable lookup unavailable/
throw and invocation throw). A stopped or unattempted slot cannot complete its
pair. Processed slots form an ordered prefix, with at most six lookups, six
invocations and three completed pairs; no retry creates a second record.

Later polls and terminal fail() perform finite currentness checks on a started
collector and update only terminal_context on invalidation. A failure in those
checks sets stale using captured plain data; it cannot erase the envelope or
overwrite collection.first_failure. Export is a deep plain-data copy of the
retained record and performs no host reads. fail() must still export actual
terminal diagnostic arrays if the collector's terminal check throws. A queued
callback after terminal refusal cannot add calls, reset the latch or mutate a
previously exported record. A different request cannot consume this collector.

Regardless of returned values, the minus install still refuses. No monitored
minus observer exists yet, so journal absence cannot establish full getter
silence or any accepted readback semantics. No source-default/mode equality,
V8 shape, successful install or semantic float basis is inferred from the
preparation or synthetic tests. Those conclusions require later captured
raw observations and independent audit.

## Test-First Matrix And Gates

Use wholly original synthetic fixtures and in-memory source-pin substitutions
for production predicates; never write a private-derived fixture. Preserve all
existing Node controls and Python tests. Establish meaningful RED with the old
controller, then GREEN for the new exact diagnostic collector.

- Positive complete synthetic hierarchy: six ordered method attempts once,
  seven strict diagnostics and zero admission/disposition/binding success.
- Wrong source/helper/document/revision/request/owner/path/type, added policy,
  malformed schema/projection or duplicate configuration: zero probes.
- Missing/extra/duplicate/reparented objects, changed non-target classes,
  geometry/names, ambiguous candidate, changed source text/ports/edges/leaves:
  zero probes with existing diagnostics retained.
- Every supported capability outcome is retained faithfully. Mid-call and

  retain completed results and produce explicit invalidated evidence.
- Repeated polls, replayed/mismatched commands, incomplete batches, later
  exceptions and fail() export preserve lifetime ownership and once-only
  bounds; results cannot cause install success or transfer to a second request.
- A completed collection followed by a later changed hierarchy exports the
  original immutable collection, stale=true and the actual changed terminal
  diagnostics. Lookup accessors mutating inputs cause zero invocation, methods
  are looked up once, unsafe intrinsic invocation never falls back, and an
  array-classification exception preserves the returned invocation outcome.
- Real-source read-only reconstruction independently matches the projection,
  all seven pins and both consumed/current script bindings without test
  substitutions or execution of historical code.
