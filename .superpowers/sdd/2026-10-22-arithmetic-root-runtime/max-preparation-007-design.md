## Synchronous Result And Bind Ownership

Choose a closure-backed single-use validation result over a global witness
cache or per-resolve acceptance. A cache would permit cross-poll/root/request
reuse; a truthy per-object policy inside `resolve` would admit `number` before
the full hierarchy and recreate the existing per-resolve probe path.

Each `install` poll creates a fresh local pass token. Successful plus validation
issues one opaque result whose closures capture that token, the exact passed
root/definition handles, Basic scope, all 20 original handles, all 16 Basic
handles, the three candidate handles/observations and primitive ownership
snapshots. Its issuer retains the exact issued-result reference locally. No
caller-supplied success boolean or observation array can substitute for it.

`consume` checks the same local issued result and active pass, the same root and
definition arguments already in this call stack, and unchanged current request,
revision, step, owner/path/source/helper and descriptor/policy bindings. Host
rereads are limited to APIs already used by preflight/bind: captured root
`filepath` and `parentpatcher`, captured objects' `maxclass`, child containers'
saved `varname`, and `getboxattr("patching_rect")` on the captured handles. Compare
these to the exact class/geometry decisions of that successful pass. No new
`valid`, parent-object, object-ID, liveness or wrapper-identity API is introduced.
It performs no capability call, inventory traversal, `getnamed`, `subpatcher` or
object re-resolution. Handle ownership was established in the captured parent
scope; bind uses those same handles, rather than comparing new wrappers.

The result transitions from available to consumed before the first varname
assignment/helper creation. A poll `finally` expires it on every exit, including
a non-final successful settling pass, refusal, trace exception and reschedule.
Repeated consumption, another poll/install/root/definition/request/revision or
an expired/foreign result refuses before any helper mutation. The result and
its authority never enter globals, ACKs, `roots`, Tasks or serialized evidence.
Only normal bound handles enter `roots` after bind succeeds.

Every matching-root poll still performs its own full preflight and six fresh
calls. On the final stable pass, `install` passes that pass's result to plus
`bind` immediately in the same callback. Plus bind requires and consumes it;
there is no missing-result fallback. It uses the captured Basic and 16-box map
for the existing varname assignments, 19 observer leaves and four root helpers.
It does not call `validateTree` or `resolve` again. Times/minus retain the
existing validate/re-resolve bind path. Preserve existing trace site ordering
and limits, and the closure-local terminal-failure guard before all queued
callback activity.
